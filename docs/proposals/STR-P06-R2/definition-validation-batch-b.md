# STR-P06-R2 정의 검증 배치 B 실행 기록

- 문서 ID: `STR-P06-R2-DAT-QA-EXEC-01`
- 작성 부서: 데이터팀·QA팀·PM
- 상태: 배치 생성 완료 / 사용자 블라인드 평가 대기
- 생성일: 2026-08-30
- DB 배치 ID: `2`
- 배치명: `STR-P06-R2 definition validation B v1`
- 정의 버전: `user-box-definition-v1`
- 후보 생성기: `box-candidate-research-v1`

## 1. 검증 질문

1. 시스템이 제시한 경계 안의 가격 상태를 사용자가 박스권·부분 박스·비박스·자료 부족으로 일관되게 구분할 수 있는가?
2. 후보 경계가 사용자가 생각하는 동일 가격 상태의 시작과 끝에 가까운가?
3. 가격 안정성, 방향성, 경계 명확성, 거래량 반응의 우선순위가 정의 가설 v1과 맞는가?

이번 배치는 박스권 하위 정의를 보정하는 세트다. `급락 → 박스권 → 회복 → 눌림` 전체 탐지 정확도나 매매 수익성을 검증하지 않는다.

## 2. 표본 구성

- 총 20종목, 기존 배치 1과 중복 0종목
- 기준일 5개, 기준일별 4종목
- 기준일: 2025-09-30, 2025-12-30, 2026-02-27, 2026-05-29, 2026-08-21
- 각 기준일 이전 120거래일의 강건 가격 범위를 계산하고 사분위별 1종목을 결정적 해시 순서로 추출
- 종목 유형은 주식으로 제한하고, 잘못 분류된 ETF 1건은 명칭 검수 후 같은 층의 주식으로 교체
- 표본 선정에는 기준일 이후 가격, 이후 수익률, 급등 여부, 사용자 라벨을 사용하지 않음

사분위는 정답 라벨이 아니다. 좁은 범위부터 넓은 범위까지 다양한 난이도를 균형 있게 보여주기 위한 표본 층일 뿐이다.

## 3. 블라인드·안전 통제

- 화면에서 종목 코드와 후보 생성기 명칭을 숨김
- API 일봉은 항목 cutoff 이하만 반환
- 후보 경계 종료일은 cutoff를 넘지 않음
- 미래 결과 공개 기능을 정의 검증 화면에서 제거
- 연구 패키지에서 주문·자동매매·전략 스캔 서비스 의존을 금지하는 구조 테스트 추가
- 평가 확정 성공 시 폼을 초기화하고 즉시 다음 항목을 로드

현재 블라인드는 사용자 화면 기준이다. 네트워크 응답에는 내부 종목 코드가 남아 있으므로, 독립 검증 C 전에 서버 측 익명 별칭 계약으로 강화한다.

## 4. 평가 절차

1. `/research/box-evaluation`에서 배치 `STR-P06-R2 definition validation B v1`을 선택한다.
2. `다음 블라인드 항목`을 누른다.
3. 후보를 비교하거나 시작·종료 거래일을 직접 수정한다.
4. 평가 라벨, 확신도, 판단 근거를 선택한다.
5. `PARTIAL_BOX` 또는 `INSUFFICIENT_DATA`는 설명을 반드시 작성한다.
6. 확정하면 다음 항목이 자동으로 열린다.
7. 20건 완료 후 더 이상 라벨을 수정하지 않고 PM 결과 집계를 요청한다.

## 5. 사전 고정 집계

- 라벨 분포와 확신도 분포
- 후보 그대로 수용률과 경계 수정률
- 시작·종료 경계 수정 거래일 수
- 사유 코드와 라벨의 교차표
- PARTIAL·NOT·INSUFFICIENT의 실패 사례 분류
- 동일 공통 경계 반복 여부 및 빈 폼·기본 확신도 저장 여부

이 단계에서는 정밀도, 재현율, IoU 통과 판정을 하지 않는다. 아직 사용자 정의를 보정하는 배치이므로 결과는 탐지기 v2 설계 입력으로만 사용한다.
