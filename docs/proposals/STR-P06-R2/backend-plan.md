# 백엔드팀 계획서 — 박스권 탐지 연구 계약

- 문서 ID: `STR-P06-R2-BE-PLAN-01`
- 상태: PM 검토안

## 목적

사용자 경계를 손실 없이 연구 특징으로 추출하고, 탐지기 v1과 v2를 동일 입력에서 재현·비교할 수 있는 계약을 제공한다. 전체 전략, 주문, 자동매매 서비스와는 분리한다.

## 계획

1. 기존 30개 평가의 원본 후보, 사용자 최종 경계, 라벨, 근거를 변경 불가능한 데이터셋으로 내보낸다.
2. `BASE_ONLY` 평가 범위를 명시해 전체 패턴 신호와 혼동하지 않게 한다.
3. 후보 특징에 가격대 체류율, 강건 기울기, 변동성, 이탈·복귀, 거래량 사건과 경계 근거를 버전 계약으로 추가한다.
4. 탐지기 v1/v2를 동일 스냅샷에서 실행하고 후보·특징·차이를 저장한다.
5. 사용자 경계를 덮어쓰지 않고 새 알고리즘 결과는 새 버전과 새 평가 항목으로 저장한다.
6. 수익률, MFE/MAE, 목표·손실 장벽을 박스권 정의 API 응답과 검증 집계에서 제거한다.
7. 탐지 결과를 주문 후보나 운영 전략 상태로 변환하는 의존성을 금지한다.

## API·저장 계약 목표

- 정의 가이드와 버전 조회
- 평가 세트의 블라인드 다음 항목 조회
- v1/v2 경계 비교와 차이 근거 조회
- 사용자 라벨·경계·이유·확신도 확정
- 숨은 반복 항목 매핑은 서버에만 보관
- 분류·경계 지표 집계는 세트 종료 뒤에만 공개

물리 테이블과 API 상세는 구현 직전 별도 상세 설계에 확정한다. 기존 마이그레이션은 수정하지 않고 신규 버전만 추가한다.

## 자동 검증

- cutoff 이후 극단값을 추가해도 후보·특징 불변
- 입력 순서 변화에도 결과 불변
- 사용자 경계 원본 불변과 정정 이력 보존
- 세트 간 중복 그룹 차단
- 연구 패키지에서 주문·브로커·자동매매 의존 0건
- 알고리즘·파라미터·특징 사전 버전 누락 시 생성 거부

## 산출물

- API/DB 상세 설계서
- 사용자 경계 연구 데이터 내보내기 계약
- 탐지기 v2 어댑터와 버전 비교 계약
- 누수·재현성·격리 테스트 증적

## 중단 조건

- 기존 사용자 평가 원본을 덮어써야 하는 설계
- 전체 전략 신호와 박스권 단독 라벨의 구분이 없음
- 알고리즘 버전을 지정하지 않고 결과가 저장됨
- 주문 경로와 연구 결과가 직접 연결됨
