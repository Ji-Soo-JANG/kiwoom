- 상태: 범위 수정 후 조건부 진행 권고 / PM·사용자 검토 필요

## 1. 독립 결론

다음 검증의 공식 목적은 **사용자가 판단한 박스권 시작·종료 경계를 후보 생성기가 얼마나 안정적으로 재현하는지 확인하는 것**으로 한정해야 한다. 현재 파일럿 보고서의 R2 제안에는 장기 국면 변화점 후보 생성과 경계 재현성 외에 `박스권/진입 분리 점수`, 미래 수익·손실 꼬리 재검증이 함께 들어 있다. 이들을 하나의 합격 기준으로 묶으면 박스 경계 생성기가 미래 성과에 맞춰 조정되고, 결국 전략·진입 연구가 경계 라벨에 섞인다.

위험관리·QA 부서는 R2를 다음 두 안건으로 분리할 것을 권고한다.

- `STR-P06-R2A`(이번 범위): 사용자 박스 경계 데이터셋, 장기 변화점 후보 v2, 반복 라벨, 경계 재현성 평가
- 후속 별도 제안: 급락→안정→회복→눌림 전체 단계, 진입 시점, 손실 장벽, 미래 성과와 주문 가능성

R2A에는 수익 최적화, 목표/손실 장벽 조정, 전체 전략 자격 판정, PAPER/LIVE 주문 연결을 포함하지 않는다.

## 2. 현재 코드 점검

| 점검 대상 | 현재 사실 | R2 판정 |
|---|---|---|
| `BoxCandidateGenerator` 입력 | `StoredDailyCandle`, cutoff, 연구 파라미터 | 유지 가능 |
| 후보 출력 | NARROW/EXPANDED/CONNECTED 경계와 박스 특징 | 경계 연구 범위 |
| 후보 특징 | 기간, 중앙 가격, 분위 범위, 폭, 기울기, 거래량 급증 | 경계 설명 범위 |
| cutoff | 이후 일봉 필터와 극단값 불변 테스트 존재 | 유지·강화 |
| 결과 계산 | 별도 `BoxOutcomeCalculator`와 reveal API | 기존 관찰 도구, R2 합격 기준에서 제외 |
| 주문 의존 | 연구 패키지에 broker/order/automation 의존 없음 | 아키텍처 테스트로 유지 |
| 운영 전략 의존 | 직접 의존 없음 | 새 금지 의존으로 고정 |
| 후보 앵커 | `recoveryAnchorRate`로 최근 가격 상승을 찾아 박스 종료를 제한 | 범위 모호성, v2에서 명칭·책임 재검토 필요 |

현재 생성기는 전체 급락→회복→눌림 전략을 실행하지 않고 주문 신호도 만들지 않는다. 다만 `recoveryAnchorRate`, `findRecoveryAnchor`라는 개념이 박스 경계 알고리즘에 포함돼 있다. 이를 ‘회복 단계 통과’ 또는 진입 조건으로 해석하면 범위를 침범한다. v2에서는 다음 중 하나를 선택해 문서와 코드에 고정해야 한다.

1. 가격 상태 변화점이라는 중립적 경계 신호로 재정의하고 `boundaryChange` 계열 명칭으로 변경한다.
2. 회복 조건이 꼭 필요하다면 박스 생성기 밖의 후속 전략 연구로 이동한다.

R2A 평가 지표에는 해당 앵커 이후 수익이나 손실 장벽 결과를 사용할 수 없다.

## 3. 이번 범위의 공식 입력과 출력

### 허용 입력

- cutoff 이하 시점 기준 DB 일봉 OHLCV
- 승인된 데이터 버전과 입력 해시
- 사용자 확정 박스 시작·종료 거래일
- 라벨, 확신도, 경계 판단 근거와 반복 평가 ID
- 후보 생성기 버전과 사전 잠금 파라미터

### 허용 출력

- 후보별 시작·종료 거래일과 사용자 경계 대비 거리
- 시작/종료 각각의 절대 거래일 오차
- 두 구간의 교집합/합집합 비율(IoU)
- 사용자 경계를 포함한 후보 비율
- `VALID_BOX`, `PARTIAL_BOX`, `NOT_BOX`, 데이터 부족별 경계 통계
- 동일 항목 반복 생성 결정성과 사용자 반복 라벨 일치도
- 후보 없음, 사용자 직접 추가, 데이터 품질 실패 비율

### 금지 입력·출력

- cutoff 이후 가격, MFE, MAE, 5/10/20일 수익
- TARGET/INVALIDATION 장벽과 어느 쪽이 먼저 도달했는지
- 급락·회복·눌림 전체 단계 통과 여부나 종합 전략 점수
- 매수 적합, 진입 대기, 손절가, 익절가, 수량, 예상 손익
- PAPER/LIVE 자동매매 상태, 주문·체결·포지션 데이터
- 미래 성과로 정렬하거나 선택한 후보·파라미터

## 4. R2A 평가 설계

### 4.1 데이터 분리

- 파일럿 30개는 요구사항 발견과 개발 세트로만 사용한다.
- v2 파라미터를 정한 뒤 서로 다른 cutoff의 새 표본을 봉인 평가 세트로 사용한다.
- 같은 종목·인접 cutoff가 학습과 평가 양쪽에 들어가지 않도록 그룹 분리한다.
- 사용자 수정 경계를 내보낼 때 reveal/outcome 테이블을 조인하지 않는다.
- `NOT_BOX`도 경계 후보를 억지로 맞추지 않고 ‘후보 없음’ 정확성 평가에 포함한다.

### 4.2 주 지표

수익률이 아니라 다음을 사전 등록한다.

1. 사용자 경계와 후보 경계의 거래일 IoU
2. 시작 경계 절대 오차와 종료 경계 절대 오차
3. 사용자가 선택 가능한 후보 중 허용 오차를 충족하는 비율
4. 동일 입력 반복 실행의 후보 ID·경계·특징·순서 일치율 100%
5. 반복 사용자 평가의 라벨 및 경계 일치도

기간이 길다는 이유로 오차가 작아 보이지 않도록 일수 오차와 IoU를 함께 공개한다. 최고 후보만 보고하지 않고 모든 후보 유형과 `USER_ADDED` 비율을 공개한다.

### 4.3 후속 성과의 취급

기존 `box-outcome-v1`과 파일럿 후속 성과는 삭제하지 않는다. 하지만 R2A에서는 다음 원칙을 적용한다.

- 후보 생성·파라미터 확정과 봉인 경계 평가가 끝날 때까지 outcome을 연구자에게 숨긴다.
- outcome은 R2A 통과/실패, 후보 순위, 파라미터 선택에 사용하지 않는다.
- R2A 완료 후 참고 부록으로 공개할 수 있으나 ‘경계 재현성’과 별도 표로 제시한다.
- 수익·MAE·장벽을 개선하려는 변경은 새로운 전략/진입 연구 제안과 사용자 승인을 요구한다.

## 6. 승인·완료 차단 조건

다음 중 하나라도 발생하면 R2A를 중단하고 범위를 다시 승인받는다.

- 미래 수익, MAE/MFE 또는 장벽 결과로 후보 파라미터를 선택한다.
- 급락·회복·눌림 전체 단계나 진입 점수를 R2A 완료 기준에 포함한다.
- 후보 또는 경계 DTO에 매수·손절·목표·수량·주문 가능 판정을 추가한다.
- 연구 코드가 운영 전략, 위험, 주문, 포지션 또는 자동매매 서비스를 호출한다.
- 파일럿에서 공개된 outcome을 봉인 평가처럼 재사용한다.
- 사용자 경계 원본을 v2 후보로 덮어쓰거나 `USER_ADDED`를 자동 탐지 성공으로 집계한다.
- NOT_BOX·데이터 부족·후보 없음 사례를 공식 결과에서 제외한다.
- 사용자가 확정한 평가 또는 잠금 파라미터를 같은 버전에서 수정한다.
- 박스 경계 재현성 결과만으로 전략 승격이나 주문 연결을 제안한다.

## 7. 완료 기준

1. R2A 목적·비목적과 경계 전용 주 지표가 사전 잠금된다.
2. 사용자 경계 학습 데이터에 cutoff 이후 가격·성과·장벽·주문 자료가 없음을 자동 검증한다.
3. 장기 변화점 후보 v2가 동일 입력에서 100% 결정론적으로 재현된다.
4. 새 봉인 표본이 파일럿/개발 종목·cutoff 그룹과 분리된다.
5. 후보 전체에 대해 IoU, 시작/종료 오차, 후보 없음과 USER_ADDED 비율을 공개한다.
6. 반복 사용자 평가의 라벨·경계 일치도를 별도 보고한다.
7. `R2-QA-01~10`과 기존 연구 격리·cutoff 테스트가 통과한다.
8. 평가 전후 전략 선택, 자동매매, 주문, 체결, 포지션 상태가 변하지 않는다.
9. 결과 보고서가 경계 재현성과 후속 성과를 별도 절로 분리한다.
10. 급락·회복·눌림 및 진입·청산 연구는 별도 부서 제안과 사용자 승인을 기다린다.

## 8. 미결정 사항

- 경계 IoU와 시작/종료 오차의 목표값
- 사용자 경계를 한 점 정답으로 볼지 허용 범위를 함께 라벨할지
- 반복 평가 비율과 평가자 내 일치도 기준
- 장기 변화점의 중립적 정의 및 `recoveryAnchor` 제거/이동 여부
- 동일 종목의 cutoff 간 최소 간격과 그룹 분리 단위
- 새 표본의 시장 국면·업종·유동성 층화 비율
- 후보 없음이 정답인 NOT_BOX의 평가 방법

## 9. 최종 권고

파일럿 보고서의 R2 제안 1·2·4·5는 R2A 경계 재현성 범위로 조정하여 진행할 수 있다. 제안 3의 진입 점수와 제안 6의 손실 꼬리·수익 재검증은 R2A에서 제외하고 후속 전략·성과 검증 제안으로 분리해야 한다.

PM은 이 범위 조정안을 사용자에게 승인받기 전 장기 후보 v2나 진입 점수 구현을 시작하지 않는 것이 적절하다.
