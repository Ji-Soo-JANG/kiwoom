# 데이터팀 계획서 — 박스권 정의 학습·검증 데이터

- 문서 ID: `STR-P06-R2-DAT-PLAN-01`
- 상태: PM 검토안

## 목적

사용자 정의 이해에 쓰는 자료와 탐지 성능을 최종 검증하는 자료를 분리한다. 종목 선택과 기준일 이후 정보가 후보 선정에 섞이지 않도록 모든 표본을 시점 일관 방식으로 동결한다.

## 데이터 세트 구분

| 세트 | 구성 | 용도 |
|---|---:|---|
| 보정 세트 A | 기존 평가 30개 | 정의 가설과 탐지기 개발 |
| 정의 확인 세트 B | 신규 20개 | 정의 초안 사용자 확인, 개발에 사용 가능 |
| 독립 검증 세트 C | 신규 60개 | 구현 동결 후 단 한 번 성능 검증 |
| 반복 평가 세트 R | C 중 12개를 순서·표현을 달리해 재제시 | 사용자 자기 일치도 측정 |

사용자 작업량은 신규 92회다. 20개 정의 확인 후 중간 승인을 받고, 독립 60개와 숨은 반복 12개를 별도 회차로 진행한다.

## 독립 검증 표본 층화

- 탐지기 v2 양성 후보 20개
- 경계 근처 hard negative 20개
- 해당 기준일 유니버스의 결정론적 무작위 종목 20개

층화 표본의 단순 합산 정밀도를 자연 유니버스 정밀도로 표현하지 않는다. 층별 결과를 각각 보고한다. 최소 5개의 서로 다른 기준일과 서로 다른 시장 상태를 사용하며 한 기준일에 12개를 넘기지 않는다.

## 시점 일관성과 누수 차단

- 표본 선정, 특징 계산, 차트는 모두 `trade_date <= asOf`만 사용한다.
- 과거 기준일 표본은 그 기준일 당시 유니버스만 사용한다.
- 최신 스캔 결과로 과거 기준일 종목을 선택하지 않는다.
- 이후 수익률, 이후 급등 여부, 현재 종목 상태를 표본 선정에 사용하지 않는다.
- 동일 종목 또는 경계가 겹치는 기간은 세트 간 한 그룹으로 묶어 중복을 막는다.
- 입력 일봉 정렬값, 종목 스냅샷, 코드·알고리즘·파라미터 버전의 해시를 잠근다.

## 품질 정책

- 잘못된 OHLC, 음수 거래량, 중복 거래일은 `BLOCKED`
- 거래정지·장기 결측·기업행사 의심은 경고와 원자료를 표시하고 자동 정답에서 제외
- 데이터 이력 부족은 `INSUFFICIENT_DATA`로 분리
- 품질 사유로 제외할 때 사용자 라벨이나 탐지 결과를 본 뒤 결정하지 않음

## 산출물

- 세트 A/B/C/R 표본 명세와 SHA-256
- 종목·기준일·표본층·중복 그룹·데이터 품질 목록
- 미래 데이터 차단 SQL과 검증 결과
- 제외 항목 및 사전 고정 사유 보고서
- 평가 완료 후에만 공개하는 세트 구성 감사 자료

## 중단 조건

- 기준일 당시 유니버스를 재현할 수 없음
- 세트 간 종목·기간 중복을 통제할 수 없음
- 입력 해시가 평가 도중 변경됨
- 품질 차단 표본이 사용자 평가에 정상 자료처럼 노출됨
