# STR-P06-R2 경계 검증 C0 보완 구현·배치 준비 보고

- 문서 ID: `STR-P06-R2-PM-C0-PREP-01`
- 승인일·완료일: 2026-08-30
- 상태: 보완 구현 완료 / 사용자 평가 대기
- 신규 DB 배치 ID: `3`
- 배치명: `STR-P06-R2 boundary validation C0 v1`

## 1. 승인 범위 이행

정의 검증 배치 B에서 20건 모두 후보·경계 없이 확정된 결함을 다음과 같이 보완했다.

1. 경계 결정을 `CANDIDATE`, `MANUAL`, `NO_SUITABLE_CANDIDATE`로 명시 저장한다.
2. `VALID_BOX`, `PARTIAL_BOX`는 후보 선택 또는 직접 시작·종료 경계가 필수다.
3. `NOT_BOX`, `INSUFFICIENT_DATA`, `DATA_QUALITY_ISSUE`는 `적합 후보 없음`을 명시해야 한다.
4. 후보 선택 방식은 저장된 후보 키와 시작·종료일이 정확히 일치해야 한다.
5. 직접 지정 방식은 후보 키를 제거하고 시작·종료일만 저장한다.
6. 빈 후보 키를 NULL로 정규화하고 교차 필드 규칙을 백엔드에서 다시 검증한다.
7. 마지막 미완료 항목 확정 시 배치를 `CLOSED`로 자동 전환한다.
8. 기존 배치 B는 평가 원본을 바꾸지 않고 상태만 `CLOSED`로 정리했다.

DB 마이그레이션 `V27`은 기존 평가와 호환하기 위해 과거 행의 경계 결정은 NULL을 허용한다. 신규 `box-label-v2` 확정 요청에서는 경계 결정이 필수다.

## 2. 사용자 흐름

- 후보의 `이 후보 선택`을 누르면 후보 키와 날짜가 함께 고정된다.
- 선택한 날짜를 수정하면 자동으로 `직접 경계 지정`으로 바뀌고 후보 키는 제거된다.
- `적합 후보 없음`을 누르면 후보 키와 날짜가 모두 초기화된다.
- 라벨과 경계 결정 방식이 맞지 않으면 확정 버튼이 비활성화된다.
- 화면 우회를 시도해도 백엔드가 같은 규칙으로 요청을 거부한다.
- 확정 성공 후에는 다음 항목으로 자동 이동한다.

## 3. 신규 경계 검증 배치

- 총 12종목, 후보 36개
- 기준일 3개, 기준일별 4종목

- 기준일별 이전 120거래일 강건 가격 범위 사분위에서 각 1종목 추출
- 기존 배치 1·2의 50종목과 중복 0
- ETF·ETN 명칭 패턴 및 비주식 상품 제외
- 후보 cutoff 초과 0
- 미래 가격·수익·급등 여부·사용자 라벨을 표본 선정에 사용하지 않음

사분위는 정답이나 합격 기준이 아니라 다양한 가격 상태를 보여주기 위한 표본 층이다.

## 4. 이번 평가의 질문

1. 제시된 후보 중 사용자가 인정하는 경계가 있는가?
2. 후보를 그대로 인정하는가, 날짜를 직접 수정하는가?
3. 적합 후보가 없다면 그 이유는 박스권 부재·자료 부족·품질 문제 중 무엇인가?

이번 12건의 목적은 경계 입력 계약과 후보 적합성을 확인하는 것이다. 전체 패턴 탐지, 수익률, 손실 장벽, 주문 가능성은 평가하지 않는다.

## 5. 평가 후 고정 집계

- 경계 결정 방식별 건수와 비율
- VALID·PARTIAL 중 후보 그대로 수용률
- 직접 수정된 시작·종료 거래일 차이
- 후보 구간과 사용자 구간의 IoU
- 후보 유형별 수용·수정·거부율
- NOT·INSUFFICIENT·품질 문제의 적합 후보 없음 비율과 사유
- 빈 후보 키 또는 양쪽 경계 NULL로 저장된 긍정 라벨 수: 반드시 0
- 최종 항목 확정 후 배치 상태: 반드시 `CLOSED`
