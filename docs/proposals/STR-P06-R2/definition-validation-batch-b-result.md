## 1. PM 요약

사용자는 신규 20개 블라인드 항목의 라벨 평가를 모두 완료했다. 결과는 `VALID 2`, `PARTIAL 8`, `NOT 7`, `INSUFFICIENT 3`이다. 판단 근거는 정의 가설 v1의 계층과 강하게 일치했다. VALID는 모두 `STABLE_RANGE + LOW_SLOPE`, NOT은 모두 `BOUNDARY_AMBIGUOUS`, PARTIAL은 안정성 일부를 인정하면서 국소 급등락·높은 변동성을 허용하지 않는 형태였다. 거래량 급증은 여러 라벨에 걸쳐 나타나 독립 판정 기준이 아님이 다시 확인됐다.

다만 20건 모두 `selected_candidate_key=''`, `final_start_date=NULL`, `final_end_date=NULL`로 확정됐다. 따라서 후보 수용률, 경계 수정률, 시작·종료 오차, IoU를 계산할 정답 경계가 없다. 이번 배치로 사용자의 **형태 분류 기준은 보강**됐지만 시스템이 사용자의 **박스 경계를 잘 찾는지는 전혀 검증되지 않았다**.

PM 판정은 `부분 완료`다. 정의 가설 v2 초안은 만들 수 있으나 탐지기 v2 구현·성능 주장·다음 독립 검증으로 승격할 수 없다.

## 4. 판단 근거 교차 분석

| 라벨 | 주요 근거 | 관찰 |
|---|---|---|
| VALID | `STABLE_RANGE` 2/2, `LOW_SLOPE` 2/2 | 안정 범위와 낮은 방향성이 함께 필요 |
| PARTIAL | `LOW_SLOPE` 5/8, `STABLE_RANGE` 4/8, `VOLUME_SPIKES` 4/8 | 전체 흐름은 인정하되 국소 변동·예외 때문에 완전 유효로 보지 않음 |
| NOT | `BOUNDARY_AMBIGUOUS` 7/7, `VOLUME_SPIKES` 6/7 | 경계 불명확성이 가장 강한 거부 근거 |
| INSUFFICIENT | LOW_SLOPE·변동성 수축·거래량 급증 각 1건 | 일부 특징이 있어도 관찰 맥락이 부족하면 판정 보류 |

거래량 급증은 PARTIAL 4건, NOT 6건, INSUFFICIENT 1건에서 나타났다. 거래량이 터졌다는 사실은 사용자가 찾는 장기 박스권의 관심 특징이지만 박스권 자격을 부여하지 않는다. 가격 상태와 경계 판단을 먼저 하고 거래량 사건은 그 안에서 해석해야 한다.

## 5. 자유 의견에서 확인한 의미

PARTIAL 8건의 설명은 다음 세 유형으로 모인다.

1. 전체 흐름은 비슷하지만 고점·저점 간격 또는 변동성이 크다.
2. 구간 일부에 급등·급락이나 한 번의 상승 후 하락이 섞여 있다.
3. 후보 일부 구간은 박스권이지만 전체 후보를 하나의 박스로 인정하기 어렵다.

즉 사용자는 단순히 좁은 가격 폭만 보지 않는다. 전체적으로 같은 가격 상태인지 인정하면서도 내부의 큰 변동, 국소 국면 변화, 후보 경계의 과도한 확장을 별도로 감점한다.

INSUFFICIENT 3건은 모두 “판단하기에 데이터가 부족하다”는 취지였다. 일봉 개수만이 아니라 앞뒤 국면을 판별할 문맥 길이가 화면에 충분한지 검토해야 한다. VALID 1건에도 데이터 양이 적다는 의견이 있어, 자료량은 자동 탈락선이 아니라 판단 신뢰도와 함께 기록해야 한다.

## 6. 가격 안정성 사분위 비교

표본은 기준일별 120거래일 강건 가격 범위를 네 사분위로 나눴다.

| 사분위 | 주요 결과 |
|---|---|
| 가장 좁음(Q1) | PARTIAL 4, NOT 1 |
| Q2 | VALID 1, PARTIAL 2, NOT 1, INSUFFICIENT 1 |
| Q3 | PARTIAL 2, NOT 3 |
| 가장 넓음(Q4) | VALID 1, NOT 2, INSUFFICIENT 2 |

좁은 가격 범위만으로 VALID가 되지 않았고 가장 넓은 층에서도 VALID가 1건 나왔다. 따라서 120거래일 강건 범위의 절대 임계값은 사용자 박스권 정의가 아니다. 실제 경계가 전체 120일보다 짧거나 다른 가격 상태를 잘라냈을 가능성이 있으므로, 변화점과 국소 구간 분할이 우선돼야 한다.

## 7. 사용자 박스권 정의 v2 초안

> 박스권은 고정된 기간이나 단일 가격 폭 임계값이 아니라, 앞뒤 국면과 구별되는 하나의 가격 상태다. 구간 전체가 비교적 안정적이고 지속적인 단방향 추세가 중심이 아니어야 한다. 일부 거래량 급증과 제한적인 일시 이탈은 허용할 수 있지만, 큰 급등락이나 서로 다른 가격 상태가 섞이면 PARTIAL 또는 NOT으로 본다. 거래량 급증은 관심 특징이지 박스권의 독립 자격 조건이 아니다. 데이터 기간은 자격 조건이 아니라 경계 판단에 필요한 문맥과 확신도의 요소다.

판정 우선순위는 다음과 같이 유지한다.

1. 하나의 가격 상태인지와 경계가 설명 가능한지
2. 내부 가격 분포와 이탈이 안정적인지
3. 지속 방향성이 중심 구조인지
4. 거래량 급증 뒤 가격이 기존 상태로 복귀·유지되는지
5. 앞뒤 국면을 판단할 문맥이 충분한지

이 문구는 분류 자료로 만든 초안이다. 실제 시작·종료 경계 검증 전에는 확정 정의로 승격하지 않는다.

## 8. 부서별 검토

### 전략연구팀

- 정의 가설의 계층 구조는 사용자 판단과 대체로 일치한다.
- 절대 가격 폭과 고정 기간을 하드 게이트로 사용하면 안 된다.
- PARTIAL을 학습·검증에서 버리지 말고 `국소 이상`, `상태 혼합`, `경계 과확장`으로 세분화해야 한다.
- 경계 자료가 없어 동적 변화점 탐지기 파라미터 설계는 보류한다.

### 데이터팀

- 표본의 시점 분산, 기존 종목 중복 차단, 미래 데이터 차단은 충족했다.
- 선택 후보·최종 경계 누락을 허용한 평가 계약 때문에 핵심 정답 필드가 100% 결측이다.
- 데이터 부족 사유를 단순 문장 외에 `문맥 부족`, `일봉 부족`, `품질 문제`로 구조화해야 한다.

### 프론트엔드팀

- 확신도 직접 선택, 설명 필수, 자동 다음 이동은 정상 작동했다.
- 라벨만 선택하면 후보나 경계 없이 확정 가능한 것이 주 결함이다.
- `후보 선택`, `직접 경계 지정`, `적합 후보 없음` 중 하나를 반드시 명시하도록 화면 계약을 바꿔야 한다.
- NOT과 INSUFFICIENT는 경계를 요구하지 않을 수 있지만 “적합 후보 없음” 사유를 명시 저장해야 한다.

### 백엔드팀

- commit 요청 검증에서 라벨별 경계 필수 규칙이 없다.
- 빈 후보 키가 정상 문자열처럼 저장됐다. 공백 정규화와 교차 필드 검증이 필요하다.
- 모든 항목 확정 후 배치를 `CLOSED`로 전환하는 상태 갱신이 필요하다.
- 독립 검증 C 전에는 종목 코드와 후보 유형을 서버 응답에서도 익명화해야 한다.

### QA·검증팀

- 분류 결과는 분석 가능하지만 사전 고정한 경계 지표는 전부 산출 불가다.
- UI와 API 모두 라벨별 필수 필드 조합 테스트가 필요하다.
- 경계 재검증에서는 성공 경로뿐 아니라 후보 없음, 수동 경계, 부분 후보, 자료 부족을 각각 계약 테스트한다.

### 위험관리·매매시스템팀

- 수익률·손실 장벽·주문과 분리된 상태는 유지됐다.
- 이번 결과를 전체 패턴 성공이나 매매 가능성으로 해석해서는 안 된다.
- 경계 검증을 통과하기 전 탐지 결과를 PAPER/LIVE 후보로 연결하지 않는다.

### 운영·보안팀

- 로컬 DB에만 평가가 저장됐고 비밀정보를 문서나 Git에 포함하지 않았다.
- 배치 상태가 READY로 남는 문제는 완료 배치 재평가·운영 혼동 위험이 있으므로 상태 전이를 보완한다.

## 10. 다음 승인 안건

PM은 다음의 한정된 보완 작업을 권고한다.

1. 라벨별 후보·경계 필수 규칙을 프론트와 백엔드에 동시에 구현한다.
2. `후보 선택 / 직접 경계 / 적합 후보 없음`을 명시 저장한다.
3. 모든 항목 완료 시 배치를 자동 종료한다.
4. 이번 20건의 라벨·의견은 보존하고 덮어쓰지 않는다.
5. 경계 검증용 신규 12건을 생성해 시작·종료 경계와 후보 판단만 재평가한다.
6. 12건 완료 후 경계 수용률·수정률·IoU를 보고하고 탐지기 v2 구현 승인을 다시 요청한다.

신규 12건은 이번 20건 및 기존 30건과 종목이 겹치지 않아야 하며, 이후 수익과 전체 패턴 결과는 계속 숨긴다.
