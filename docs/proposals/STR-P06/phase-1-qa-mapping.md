## 1. 판정 원칙

- `통과`는 자동 테스트가 구현되어 실제 실행에 성공한 경우만 표시한다.
- `기반`은 테스트 경계 또는 공통 검증만 존재하고 기능 구현과 결합 검증이 남은 상태다.
- `미구현`은 1단계 또는 후속 단계에서 별도 구현이 필요한 상태다.
- 연구 평가 통과는 전략 승격이나 주문 허가를 의미하지 않는다.

## 3. 독립 아키텍처 안전망

`ResearchIsolationArchitectureTest`는 컴파일된 `com.example.kiwoom.research` 클래스 전체를 검사한다. 특정 구현 클래스 이름에 결합하지 않으므로 PH1-01~07의 병렬 구현 중에도 다음 경계를 유지한다.

- `BrokerAdapter` 및 broker 패키지 참조 금지
- `PaperOrderService`, `LimitedTradingService`, `AutoTradingControlService`, `PaperRiskService` 참조 금지
- PAPER·제한매매·자동매매 repository 참조 금지
- 주문·체결·PAPER 계좌·포지션·제한 후보·자동매매 제어 테이블 SQL 문자열 금지

이 검사는 안전 경계의 최소 조건이다. reflection, 동적 SQL, HTTP 우회와 실제 DB 변경까지 증명하려면 `P06-QA-029~031` Spring/PostgreSQL 통합 테스트가 추가로 필요하다.

## 4. PH1-08 완료 차단 조건

다음 중 하나라도 남으면 PH1-08을 완료 처리하지 않는다.

- 연구 패키지에서 주문·브로커·자동매매 참조가 검출된다.
- cutoff 이후 극단 일봉을 추가했을 때 입력 해시·후보·공개 전 응답이 달라진다.
- 요청의 날짜나 limit으로 cutoff를 우회할 수 있다.
- 동일 입력·설정에서 후보 ID, 경계, 특징 또는 정렬이 달라진다.
- COMMITTED 원본을 update/delete하거나 같은 ID로 내용을 바꿀 수 있다.
- 동시 draft 수정이 조용히 덮어써진다.
- 평가·commit·reveal 호출 전후 주문 및 자동매매 상태가 변한다.
- 공개 전 DTO가 미래 결과의 값 또는 존재 여부를 노출한다.
