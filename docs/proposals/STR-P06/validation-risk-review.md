# STR-P06 QA·성과검증·위험 독립 검토서

- 문서 ID: `STR-P06-REVIEW-QA-RISK-01`
- 상태: 조건부 승인 권고안 / PM·사용자 검토 대기
- 작성 부서: QA·검증팀, 성과검증팀, 위험관리팀 공동 독립 검토
- 기준일: 2026-08-29
- 검토 대상: 실제 DB 일봉에서 복수 안정 구간 후보를 제시하는 GUI, 사용자 선택·수정·라벨 확정 및 잠금, 전략 평가·비교와 후속 성과 공개 체계
- 연결 요구사항: `STR-004~005`, `DAT-001~004`, `PRM-001~003`, `NFR-002~003·006·008`
- 선행 제안: `STR-P05` 실제 사례·반례 라벨 데이터셋과 파라미터 민감도 보고서
- 중요 제한: 이 문서는 구현 승인이 아니며 코드·DB·API·주문 동작 변경을 허가하지 않는다.

## 1. 검토 결론

STR-P06의 목적이 전략 판단을 사람이 검토 가능한 자료로 만들고, 평가 시점의 결론과 이후 실제 성과를 분리하여 공개하는 것이라면 연구 신뢰성 향상에 필요하다. 다만 사용자가 선택한 사례만 평가하거나, 평가 후 라벨·기준·표본을 수정할 수 있거나, 같은 평가 자료를 반복해서 파라미터 조정에 사용하면 결과가 좋아 보여도 일반화 성능의 근거가 되지 않는다.

QA·성과검증·위험 부서는 다음 조건을 전제로 **조건부 승인 권고**한다.

1. 평가 대상, 기준일, 데이터 버전, 전략 버전, 라벨 정의와 지표를 실행 전에 확정한다.
2. 확정된 평가 묶음은 잠그고 수정하지 않는다. 오류 정정은 원본을 보존한 새 버전으로만 수행한다.
3. 신호 기준일 이후 데이터는 전략 입력과 당시 사용자 판정 화면에서 완전히 차단한다.
4. 사용자 라벨은 단독 정답으로 취급하지 않고 독립 검토·불일치·확신도를 보존한다.
5. 골든 사례뿐 아니라 반례, 애매 사례, 데이터 이상 사례와 무신호 기간을 함께 고정한다.
6. 평가 확정 결과와 이후에 관측된 성과를 별도 단계·별도 필드로 공개한다.
7. 이 기능은 연구 전용이며 자동매매 ON/OFF, 후보 승인, 주문, 포지션, 위험 한도와 기술적으로 완전히 분리한다.

위 조건 중 하나라도 설계에서 빠지면 STR-P06은 승인하지 않는다.

## 2. 검토 대상의 책임 경계

### 포함해야 하는 기능

- 기준일 당시 DB 일봉만으로 한 종목의 복수 안정 구간 후보를 동일 규칙으로 생성·표시
- 각 후보의 시작·종료일, 특징값, 생성 알고리즘 버전과 정렬 근거 표시
- 사용자가 시스템 후보를 선택하거나 경계를 수정하되 원 제안과 수정 이력을 함께 보존
- 특정 기준일에 전략이 알 수 있었던 자료만 재현하는 평가 케이스
- 사용자 및 검토자의 패턴 라벨·확신도·근거 기록
- 평가 묶음의 초안, 확정, 잠금, 폐기와 새 버전 생성
- 전략별 동일 평가 묶음 실행과 결과 비교
- 평가 확정 후 정해진 관측기간이 지난 시점의 후속 성과 계산·공개
- 골든·반례·애매·데이터 품질 실패 케이스의 회귀 검증
- 평가 실행과 수정 이력의 감사·재현 정보

### 포함하면 안 되는 기능

- 평가 화면에서 자동매매를 켜거나 전략을 LIVE/PAPER로 승격하는 기능
- 평가 결과를 주문 후보나 제한 매매 후보로 자동 전달하는 기능
- 사용자 라벨에 맞춰 운영 전략 파라미터를 자동 수정하는 기능
- 이후 주가를 본 뒤 과거 라벨·판정·평가 지표를 덮어쓰는 기능
- 수익이 좋은 표본만 선택해 공식 성과로 게시하는 기능
- 잠긴 평가 묶음을 삭제하거나 같은 버전으로 재작성하는 기능

## 3. 핵심 위험 분석

### 3.1 평가 선택 편향

사용자가 기억하는 성공 사례, 눈에 잘 띄는 급등 종목 또는 현재 보유 종목만 등록하면 평가 집합이 실제 시장 분포를 대표하지 않는다. 전략이 놓친 종목만 찾는 방식도 반대로 재현율을 과장할 수 있다.

필수 통제:

- 사용자 지정 사례 세트와 시스템이 규칙에 따라 추출한 무작위/전수 표본을 분리한다.
- 시장, 연도, 시가총액, 유동성, 업종, 시장 국면별 포함 수를 공개한다.
- 후보가 전혀 없던 날짜와 급등하지 않은 다수 종목도 모수에 포함한다.
- 평가 제외는 사전에 정한 데이터 품질 사유만 허용하고 종목·수익을 본 뒤 제외하지 않는다.
- 제외 전후 표본 수와 제외 사유를 결과에 항상 표시한다.

### 3.2 미래 데이터 누수

최종 상승폭, 이후 최고가, 사후 수정된 종목 상태, 미래 거래량 또는 전체 기간으로 계산한 정규화 값이 기준일 화면이나 전략 입력에 노출되면 라벨러와 전략 모두 미래 정보를 사용하게 된다.

필수 통제:

- 평가 입력의 최대 시각을 `asOfDate`로 고정하고 쿼리·서비스·DTO 경계에서 이후 행을 거부한다.
- 종목 마스터, 거래 가능 상태, 수정주가, 시장·업종 특징도 시점 기준 스냅샷을 사용한다.
- 라벨 작성 단계에서는 기준일 이후 차트·성과·뉴스를 숨긴다.
- 후속 성과는 평가 확정 후 별도 권한과 별도 화면에서만 공개한다.
- 동일 케이스의 `inputMaxDate <= asOfDate`를 자동 검사하고 위반 시 전체 실행을 무효화한다.
- 워크포워드에서 파라미터·임계값은 각 학습 구간에서만 정하고 다음 구간에 고정한다.

### 3.3 평가 후 기준 변경과 선택적 공개

나쁜 결과를 본 후 라벨 정의, 관측기간, 성공 기준, 비용 또는 제외 기준을 바꾸면 사후 최적화다.

필수 통제:

- 평가 계획에 5/10/20거래일 등 관측 지평, 목표·손절 판정, 비용, 동시 충족 순서와 지표를 사전 등록한다.
- `DRAFT → FROZEN → EVALUATED → OUTCOME_PUBLISHED` 단방향 상태를 사용한다.
- FROZEN 이후 변경은 기존 평가 ID를 유지한 수정이 아니라 새 버전·변경 사유·부모 버전으로 남긴다.
- 결과가 나쁜 전략과 무신호 실행도 성공 결과와 같은 방식으로 게시한다.
- 공개 시점이 되지 않은 후속 성과는 `미확정`으로 표시하고 중간값을 최종 성과처럼 집계하지 않는다.

### 3.4 사용자 라벨 신뢰성

사용자가 의도한 패턴을 표현하는 라벨은 중요한 연구 자료지만 객관적 진실과 동일하지 않다. 패턴의 경계가 모호하고 이후 결과를 알고 라벨하면 확증편향이 생긴다.

필수 통제:

- 라벨은 최소 `POSITIVE`, `NEGATIVE`, `AMBIGUOUS`, `DATA_INVALID`로 구분한다.
- 확신도, 판단 근거, 보이는 데이터 범위, 작성자, 작성 시각과 라벨 정의 버전을 저장한다.
- 최소 표본에 대해 두 명 또는 두 번의 독립 라벨을 확보하고 일치율을 공개한다.
- 불일치는 다수결로 숨기지 않고 원 라벨과 조정 결론을 모두 보존한다.
- 라벨러가 후속 성과를 본 상태인지 `blinded/unblinded`로 구분한다.
- 전략 평가의 공식 골든 세트에는 정의가 안정되고 검토 일치 기준을 통과한 사례만 포함한다.
- 애매 라벨은 정확도 분모에서 임의 제외하지 않고 별도 성능군으로 보고한다.

### 3.5 골든 세트 과적합

고정 골든 세트는 회귀 방지에는 유용하지만 반복 조정에 사용하면 사실상 학습 데이터가 된다.

필수 통제:

- `연구/조정 세트`, `회귀 골든 세트`, `봉인 최종 평가 세트`를 물리적·논리적으로 구분한다.
- 개발자는 봉인 세트의 개별 종목과 정답을 실행 전 열람하지 않는다.
- 골든 세트 성능은 회귀 실패 탐지에 사용하고 파라미터 선택 근거로 반복 사용하지 않는다.
- 봉인 세트 공개 또는 반복 사용 후에는 새 외부 기간을 최종 평가 세트로 지정한다.

### 3.6 복수 박스 후보 GUI 편향

동일 일봉에서 여러 안정 구간이 가능할 때 최고 점수 하나만 보여주면 시스템의 선호가 사용자 라벨에 영향을 준다. 반대로 사용자가 결과가 좋아 보이는 구간만 자유롭게 그리면 사후 선택 편향이 발생한다.

필수 통제:

- 후보 생성기는 동일 입력에서 복수 후보 전체와 안정적인 후보 ID를 결정론적으로 생성한다.
- 기본 정렬 기준과 점수 구성은 평가 전에 고정하며, 순위가 라벨 정답처럼 보이지 않게 한다.
- GUI는 같은 가격축·거래일축에서 모든 후보를 구분해 표시하고 확대/축소가 실제 경계 날짜를 바꾸지 않아야 한다.
- 사용자가 후보를 선택하지 않거나 `해당 없음`을 선택할 수 있어야 한다.
- 경계를 수정할 때 원 후보 ID, 원 날짜, 수정 날짜, 수정 이유와 작성자를 저장한다.
- 시스템 미제안 구간을 사용자가 새로 지정한 경우 `USER_ADDED`로 분리하여 탐지기의 성공으로 집계하지 않는다.
- 후보 선택 단계에서는 `asOfDate` 이후 봉, 후속 수익, 미래 이벤트와 성과 순위를 완전히 숨긴다.
- 복수 후보 중 어느 것을 선택했는지뿐 아니라 선택하지 않은 후보도 평가 케이스에 보존한다.

## 4. 필수 평가 자료 구성

| 세트 | 목적 | 필수 포함 | 사용 제한 |
|---|---|---|---|
| 사용자 사례 세트 | 사용자 의도 해석 | 긍정·부정·애매, 근거와 확신도 | 공식 성과 단독 사용 금지 |
| 골든 회귀 세트 | 판정 변경 감지 | 장·단기 안정구간, 경계 사례, 대표 시장 국면 | 파라미터 최적화 금지 |
| 반례 세트 | 오탐·위험 검증 | 일시 급등, 유동성 부족, 하락 지속, 기업행사, VI·정지, 데이터 이상 | 통과 시 결함으로 처리할 항목 명시 |
| 무작위/전수 표본 | 실제 분포 평가 | 무신호 날짜와 비후보 종목 포함 | 사후 선택·제외 금지 |
| 봉인 시간외 표본 | 일반화 평가 | 조정 기간 이후 시장 구간 | 결과 확인 전 계획 잠금 |

반례 세트에는 최소한 다음 유형을 포함한다.

- 급락 없이 단순 상승한 종목
- 안정 구간 없이 계속 하락하거나 변동성이 큰 종목
- 거래량 급증은 있으나 가격 구조가 유지되지 않은 종목
- 회복이 과도하거나 이미 눌림이 끝난 과거 완료 패턴
- 액면분할·권리락 등 기업행사를 급락으로 오인할 수 있는 종목
- 상장폐지·거래정지·관리·투자위험·유동성 부족 종목
- 상한가·갭으로 실제 진입 가격을 얻을 수 없는 종목
- 누락·중복·0 가격·수정 전후 불일치 데이터

## 5. 평가 확정·잠금·후속 공개 규칙

### 확정 전 필수 메타데이터

- 평가 계획 ID와 버전
- 평가 묶음 ID, 케이스 목록 해시와 생성 규칙
- 각 케이스의 `asOfDate`, 시점 기준 종목/가격 데이터 버전
- 전략 코드 버전, 전략 정의/파라미터 해시
- 라벨 정의 버전과 라벨 상태
- 관측 지평, 성공·실패·애매 판정 규칙
- 비용·슬리피지·체결 가능성 가정
- 주 지표와 보조 지표, 비교 기준 전략
- 제외 기준과 최소 표본 수
- 작성·검토·확정 주체 및 시각

### 잠금 원칙

- 잠금은 애플리케이션 상태만이 아니라 DB 제약·감사 이벤트·내용 해시로 검증 가능해야 한다.
- 잠긴 입력, 라벨, 전략 버전, 지표 정의를 바꾼 실행은 같은 평가가 아니다.
- 데이터 오류가 발견되면 원 결과를 `INVALIDATED`로 보존하고 수정 버전을 새로 만든다.
- 임의 삭제는 금지하며 개인정보·법적 삭제가 필요하면 별도 감사 가능한 삭제 정책을 따른다.

### 후속 성과 공개

- 후속 성과는 평가 확정 시 정한 거래일 지평이 모두 지난 후 계산한다.
- 중간 성과와 최종 성과를 명확히 구분한다.
- 신호가 없던 경우, 거래 불가능했던 경우, 데이터가 부족한 경우도 결과로 공개한다.
- 최대 유리 변동(MFE), 최대 불리 변동(MAE), 종가/고가 기준 상승, 손절·목표 선도달, 거래 가능성과 비용 후 가상 성과를 분리한다.
- 후속 성과는 라벨을 자동 변경하지 않는다. 라벨과 결과의 불일치는 별도 분석 자료가 된다.

## 6. 성과 비교 원칙

단순 적중률이나 누적 수익률 하나로 전략을 평가하지 않는다.

### 탐지 품질

- 전체 후보 수와 일별 분포
- Precision, Recall, F1과 클래스 불균형을 고려한 PR-AUC
- Precision@K 및 무신호 비율
- 긍정·부정·애매 라벨별 혼동행렬
- 시장·연도·업종·유동성·국면별 편차

### 후속 가격 결과

- 5/10/20거래일 MFE·MAE 분포
- 목표와 무효화 가격 중 먼저 도달한 비율
- 평가 시점 이후 진입 가능한 가격이 실제 있었던 비율
- 상·하한가, VI, 거래정지, 갭으로 거래가 불가능했던 비율

### 가상 매매 성과

- 수수료·세금·슬리피지 후 기대값
- 최대 낙폭, Profit Factor, 평균 손익비와 연속 손실
- 회전율, 거래대금 대비 주문 비율과 체결 민감도
- 현금 보유, 시장 지수, 현 운영 전략과의 동일 기간 비교

### 비교 공정성

- 모든 전략은 동일 평가 세트, 동일 기준일, 동일 비용·체결 모델을 사용한다.
- 주 지표는 결과 확인 전에 하나 또는 소수로 정하고 나머지는 보조 지표로 표시한다.
- 여러 전략·임계값을 비교한 수와 선택 과정을 공개하여 다중 비교 편향을 숨기지 않는다.
- 새 전략이 일부 국면만 개선하고 다른 국면의 손실을 키우는지 별도로 공개한다.
- 통계적 불확실성은 신뢰구간 또는 부트스트랩 구간으로 표시하며 작은 표본의 순위를 확정적으로 표현하지 않는다.

## 7. 실전 주문과의 완전 분리

STR-P06은 연구 자료 시스템이다. 다음 분리는 사용자 승인 전 구현 설계의 필수 조건이다.

- 평가 서비스는 `BrokerAdapter`, `PaperOrderService`, `LimitedTradingService`, 자동매매 제어 서비스를 의존하지 않는다.
- 평가 API는 `/api/research/**` 등 주문 API와 다른 네임스페이스와 권한을 사용한다.
- 평가 DB 사용자는 주문·자동매매 제어 테이블에 쓰기 권한이 없어야 한다.
- 평가 결과에 주문 실행, 후보 승인, 자동매매 ON/OFF 링크를 제공하지 않는다.
- 평가 실행 환경에서는 `TRADING_MODE=SIGNAL_ONLY`이며 외부 주문 제출 자격 증명을 주입하지 않는다.
- 이벤트 발행을 사용하더라도 주문 소비자가 구독하는 신호 토픽/테이블과 분리한다.
- 전략 승격은 평가 결과만으로 자동 수행하지 않고 별도 PRM 검토·PM 검토·사용자 승인을 요구한다.
- 연구 결과 CSV/JSON을 다시 가져와도 주문 후보가 생성되지 않는 통합 테스트가 있어야 한다.

## 9. 승인 차단 조건

다음 중 하나라도 해당하면 PM은 구현 승인을 요청하지 않아야 한다.

- STR-P06의 정확한 목적·책임 경계와 STR-P05 관계가 제안서에 명시되지 않음
- 미래 데이터 차단을 애플리케이션 관례에만 의존하고 자동 검증하지 않음
- 평가 계획과 묶음에 확정·잠금·버전·해시·감사 규칙이 없음
- 사용자 라벨을 확신도·근거·작성 시점 없이 단일 정답으로 사용함
- 복수 박스 후보 중 최고 점수 하나만 노출하거나 사용자 수정 전 원 후보를 보존하지 않음
- 긍정 사례만 평가하거나 반례·무작위/전수·봉인 표본이 없음
- 나쁜 결과·무신호·거래불가·제외 표본을 공식 결과에서 숨길 수 있음
- 평가 후 지표·관측기간·비용·제외 기준을 같은 버전에서 변경할 수 있음
- 운영 전략과 평가 전략의 코드/파라미터 버전을 입증할 수 없음
- 평가 기능이 주문·제한 후보·자동매매 제어와 코드·권한·DB 경로 중 하나라도 연결됨
- 평가 결과가 별도 승인 없이 전략 승격이나 실제 운전 설정을 변경함
- 성과 수치가 미래 수익 보장 또는 매수 추천으로 오인될 UI·문구 통제가 없음

## 10. 완료 기준

STR-P06은 다음 증적이 모두 있을 때만 완료로 판단한다.

1. 승인된 평가 계획과 라벨 정의 문서가 버전·해시와 함께 존재한다.
2. 사용자 사례, 골든, 반례, 무작위/전수, 봉인 시간외 세트가 목적별로 분리돼 있다.
3. 모든 케이스가 시점 기준 데이터 계보와 입력 최대일 검사를 통과한다.
4. 잠금 이후 수정·삭제·덮어쓰기가 실패하고 새 버전 정정 흐름이 자동 테스트된다.
5. 평가 확정 결과와 후속 성과가 분리 저장·표시되며 선택적 공개가 불가능하다.
6. 사용자 라벨 신뢰도와 독립 일치/불일치 보고서가 생성된다.
7. 동일 조건 전략 비교와 기존 전략 기준선 비교를 독립적으로 재계산할 수 있다.
8. 모든 `P06-QA-001~031` 테스트가 통과하고 실패 증적을 보존한다.
9. 평가 실행 전후 주문·후보·포지션·자동매매 상태가 불변임을 통합 테스트로 입증한다.
10. QA·성과검증·위험관리 부서가 각각 서면 검토하고 PM 검토 후 사용자가 별도로 승인한다.

완료는 전략의 LIVE 승격이나 수익성 확정을 의미하지 않는다. STR-P06 결과는 후속 전략 연구와 승격 심사의 입력 자료일 뿐이다.

## 11. 미결정 쟁점

- STR-P06의 공식 명칭과 STR-P05 결과 중 어느 자료를 입력으로 삼을지
- 사용자 라벨을 익명 독립 재라벨할 인원과 조정 책임자
- 라벨 일치율 지표와 골든 편입 최소 기준
- 골든·반례·봉인 세트의 최소 표본과 시장 국면별 할당량
- 후속 성과 지평(5/10/20거래일 등)과 성공·무효화 선도달 정의
- 고가/종가/실제 진입 가능 가격 중 탐지 성과의 주 기준
- 비교할 기준 전략과 공식 주 지표
- 데이터 오류 발견 시 무효화 범위와 재평가 승인 권한
- 봉인 세트 열람 권한, 공개 시점과 재사용 횟수
- 사용자에게 표시할 불확실성·과적합·비추천 경고 문구
- 연구 DB와 운영 DB를 논리 권한으로 분리할지 물리적으로 분리할지

## 13. 최종 권고

PM에게 `조건부 승인 요청 준비`를 권고한다. 단, 사용자가 승인할 대상은 전략의 수익성이나 실전 사용이 아니라 **편향을 줄인 연구 평가 체계의 설계·구현 범위**여야 한다. STR-P06 구현 후에도 전략 승격과 주문 연결은 별도 제안·부서 검토·사용자 승인을 거쳐야 한다.
