# STR-P06 2단계 GUI 실행 승인 요청서

- 문서 ID: `STR-P06-PH2-PLAN-01`
- 기준일: 2026-08-29
- 상태: **사용자 실행 승인 대기**
- 선행 조건: STR-P06 1단계 완료

## 목표

1단계의 블라인드 API를 사용하여 실제 DB 일봉에서 복수 박스권 후보를 비교하고 사용자가 경계와 라벨을 남기는 연구 화면을 만든다.

## 승인 요청 범위

| 작업 ID | 작업 |
|---|---|
| `PH2-01` | 일반 종목 화면과 분리된 `박스권 평가` 연구 탭 추가 |
| `PH2-02` | 평가 과제 선택, 진행률, 다음 블라인드 항목 이동 |
| `PH2-03` | 실제 일봉·거래량 차트와 cutoff 이후 영역 비공개 표시 |
| `PH2-04` | NARROW/EXPANDED/CONNECTED 전환 및 겹쳐 보기 |
| `PH2-05` | 마우스·날짜 입력·키보드로 경계 수정 및 직접 구간 생성 |
| `PH2-06` | 라벨·확신도·근거·메모와 자동 임시 저장 |
| `PH2-07` | 확정 전 요약, 불변 확정, 충돌·오류 안내 |
| `PH2-08` | 결과 공개 정책 상태 표시; 공식 산식 미설정 시 명확한 안내 |
| `PH2-09` | 컴포넌트·API·E2E·접근성 테스트 및 부서 검토 |

## 필수 UI 원칙

- 미래 데이터는 프론트에서 숨기는 방식이 아니라 서버 응답에 존재하지 않아야 한다.
- 후보는 색뿐 아니라 ID·선 모양·텍스트로 구분한다.
- 원본 후보는 경계 수정 후에도 남겨 차이를 확인할 수 있게 한다.
- `해당 없음`, `판단 불가`, 사용자 직접 구간을 지원한다.
- 확정 직후 미래 결과를 자동 요청하지 않는다.
- 연구 화면에 자동매매 ON/OFF, 주문, 전략 승격 버튼을 두지 않는다.

## 완료 기준

- 실제 일봉으로 세 후보를 전환·겹쳐 비교할 수 있다.
- 마우스 없이도 모든 평가 입력과 확정이 가능하다.
- 임시 저장 충돌과 API 오류가 사용자가 이해할 수 있는 문장으로 표시된다.
- 확정 전 브라우저 네트워크·상태·캐시에 미래 자료가 없다.
- 프론트 단위 테스트, E2E 핵심 여정과 백엔드 전체 테스트가 통과한다.
- 완료 보고서와 3단계 검증 자료화 실행 승인안을 사용자에게 제출한다.

## 승인 요청 문구

> **STR-P06 2단계 GUI를 `PH2-01~09` 범위와 필수 UI 원칙대로 구현한다. 연구 화면은 주문·자동매매·전략 승격과 연결하지 않으며, 완료 후 부서 검토 결과와 3단계 실행안을 별도로 승인 요청한다.**
