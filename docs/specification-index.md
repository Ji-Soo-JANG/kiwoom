# Kiwoom 자동매매 시스템 설계 문서

최종 수정일: 2026-08-29
문서 상태: 초안 기준선(Baseline v0.1)

## 1. 문서 목적

이 문서 묶음은 사용자의 구상, 구현 범위, 안전 원칙과 화면 흐름을 코드 작업 전에 합의 가능한 형태로 보존한다. 이후 기능 추가와 변경은 요구사항 ID를 기준으로 추적한다.

## 2. 문서 구성과 우선순위

1. [요건 정의서](requirements-definition.md): 무엇을 왜 만들어야 하는지 정의한다.
2. [기본 설계서](basic-design.md): 시스템 경계, 구성 요소와 주요 흐름을 정의한다.
3. [상세 설계서](detailed-design.md): 전략 판정, 주문, 데이터와 장애 처리 방법을 정의한다.
4. [UI 설계서](ui-design.md): 사용자가 보는 화면과 조작 흐름을 정의한다.

현재 코드에 대한 부서별 조사와 PM 종합 검토는 [부서별 프로젝트 분석 자료](departments/README.md)에서 확인한다. 부서 보고서는 승인 전 검토 자료이며 위 설계 기준을 자동으로 변경하지 않는다.

내용이 충돌하면 `요건 정의서 → 기본 설계서 → 상세 설계서 → UI 설계서 → 기존 개별 문서` 순으로 해석한다. 실제 코드와 문서가 다르면 차이를 숨기지 않고 문서의 구현 상태에 기록한다.

## 3. 확정된 핵심 원칙

- 최종 목적은 한국 주식 현물의 **실전 자동매매**다.
- PAPER 환경은 실전 전 검증 단계이며 최종 산출물이 아니다.
- 선물·옵션·공매도·신용·미수·해외 주식·가상자산은 범위에서 제외한다.
- 핵심 패턴은 `과거 급락 → 가격 안정 구간과 간헐적 거래량 증가 → 최근 부분 회복 → 현재 눌림`이다.
- 가격 안정 구간의 고정 일수는 핵심 조건이 아니다. 수개월부터 수년까지 데이터가 보여주는 구간을 동적으로 찾는다.
- 과거에 완료된 패턴이 아니라 **현재 진입 검토가 가능한 상태**인 종목만 후보로 삼는다.
- 자동 운전 중에는 종목별 사람 승인을 요구하지 않는다. 다만 실전 운전 시작, 위험 한도 변경과 장애 후 재개에는 명시적 확인을 둔다.
- 손절·위험 차단·감사 기록은 전략 수익성보다 우선한다.

## 4. 현재 구현 상태

현재 애플리케이션에는 일봉 저장, 전략 스캔, 후보 발견, 백테스트, PAPER 주문·포지션·성과, 위험 한도와 스케줄 실행의 기반이 있다. 실제 키움 주문 어댑터는 연결되지 않았으므로 `LIVE` 요청은 실주문을 내지 않는다. 따라서 이 문서의 실전 주문·대사·복구 항목 일부는 목표 설계다.

## 5. 변경 관리

- 요구사항은 삭제하기보다 상태를 `제안/확정/보류/폐기`로 변경하고 사유를 남긴다.
- 매매 전략 변경은 새 전략 버전으로 저장하며 과거 결과를 덮어쓰지 않는다.
- 실전 운전 관련 변경은 요구사항, 실패 시 동작, 테스트 결과와 복구 방법을 함께 갱신한다.
- TODO 항목은 가능한 경우 해당 요구사항 ID를 포함한다.

## 6. 주요 미결정 사항

- 급락의 크기·속도, 회복 비율, 눌림 깊이의 최종 범위
- 동적 안정 구간 탐지 알고리즘과 최소 데이터 품질 기준
- 주문 유형, 가격 추적 방식, 허용 슬리피지와 재주문 규칙
- 주문당 금액, 최대 동시 보유 수, 일 손실·누적 낙폭 한도
- 최대 보유기간을 둘지 여부와 시간 청산 정책
- 키움 실전 API의 주문·체결·잔고 계약 및 호출 제한
- 거래일·휴장일의 공식 기준 데이터와 PC 자동 기동 방식

위 항목은 백테스트, 워크포워드, PAPER 및 모의투자 결과로 확정한다.
