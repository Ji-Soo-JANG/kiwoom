# 급등 후보 탐지·자동매매 로드맵

마지막 정리: 2026-08-22

## 목표와 원칙

목표는 한국 주식 중 `급락 → 장기 횡보(간헐적 거래량 증가) → 초기 상승 → 저거래량 눌림` 패턴을 찾고, 검증된 조건에서만 자동 주문하는 로컬 시스템을 만드는 것이다.

- 후보 탐지, 매수 판단, 주문 실행, 위험 통제를 서로 분리한다.
- 전략 기준은 고정된 정답이 아니라 백테스트로 검증할 가설로 관리한다.
- 미래 데이터가 섞이는 룩어헤드 바이어스와 상장폐지 종목이 빠지는 생존편향을 차단한다.
- 수익률보다 거래비용 반영 기대값, 최대 낙폭, 오탐률, 주문 안정성을 먼저 본다.
- 실계좌 주문은 모의투자와 관찰 모드의 통과 기준을 모두 만족하기 전에는 활성화하지 않는다.

### 대상 상품 범위

이 프로젝트의 자동매매 대상은 **KRX 국내 주식 현물 보통주의 현금 매수·보유 수량 내 매도**로 고정한다.

- 매수 후 매도하는 롱 포지션만 허용한다.
- 공매도, 신용, 미수, 대주와 보유 수량을 초과하는 매도를 금지한다.
- 주식·지수 선물, 옵션과 기타 파생상품은 데이터·전략·주문 모델에서 제외한다.
- 해외 주식, 가상자산과 NXT 주문은 범위에서 제외한다.
- ETF·ETN·리츠·스팩·우선주·관리·정리매매·거래정지 종목은 자동 진입 후보에서 기본 제외한다.
- 주문 수량, 잔고와 포지션은 항상 0 이상이어야 하며 음수 포지션을 허용하지 않는다.

## 2026년 8월 이후 실행 로드맵

아래 순서는 현재 완성된 후보 탐지, 백테스트, PAPER 진입과 위험관리 기능 다음에 진행할 작업이다. 각 단계는 앞 단계의 완료 기준을 통과해야 다음으로 넘어간다.

### R1 — 현물 PAPER 청산 사이클 완성 (코드 작업)

- PAPER 포지션마다 평균 진입가, 진입 시각, 손절가, 익절가와 최대 보유기간을 저장한다.
- `보유 → 청산 대기 → 매도 승인 → 청산 완료` 상태를 만든다.
- 손절, 익절, 최대 보유기간, 수동 청산 사유를 구분한다.
- 매도 전에 실제 보유 수량을 다시 확인하고 초과 매도와 중복 청산을 차단한다.
- 동일 봉에서 손절과 익절이 함께 충족되면 손절을 우선하는 보수적 규칙을 사용한다.

완료 기준:

- 매수부터 청산까지 한 거래가 하나의 거래 사이클로 연결된다.
- 재시도와 서버 재시작 후에도 매도 주문은 한 번만 생성된다.
- 잔고가 음수가 되거나 보유 수량보다 많은 매도가 발생하는 테스트가 모두 차단된다.

### R2 — 비용 후 최종 성과 자동 기록 (코드 작업)

- 진입·청산 체결, 양방향 수수료와 매도세를 연결한다.
- 총 실현 손익, 비용 후 순수익률, 진입·청산 슬리피지와 보유기간을 자동 계산한다.
- 완료된 거래만 전략 수익률 표본으로 사용하고 진입 체결 품질 표본과 분리한다.
- 승률, 평균 손익비, Profit Factor, 연속 손실, 최근 N건 기대값과 최대 낙폭을 제공한다.
- 성과 기준 이탈 시 킬 스위치를 활성화하고 수동 확인 없이는 재개하지 않는다.

완료 기준:

- DB 체결 합계로 다시 계산한 손익과 거래 성과가 일치한다.
- 같은 체결 이벤트를 다시 받아도 성과가 중복 집계되지 않는다.
- 성과 저하 테스트에서 신규 진입이 자동 차단된다.

### R3 — 장중 청산 판정과 승인 화면 (코드 작업)

- 저장된 장중 가격으로 손절·익절·보유기간 조건을 평가한다.
- 조건 충족 시 자동 매도가 아니라 청산 승인 후보를 생성한다.
- 승인 화면을 진입 대기, 보유, 청산 대기, 완료 거래로 분리한다.
- 현재 손익률, 손절·익절 가격, 보유기간, 청산 이유와 비용 후 결과를 표시한다.
- 가격 데이터가 오래됐거나 누락되면 청산 판단 상태를 경고하고 신규 진입을 막는다.

완료 기준:

- 기록된 가격 경로를 재생하면 동일한 청산 후보와 이유가 생성된다.
- 동일 조건의 청산 후보가 반복 생성되지 않는다.
- 키보드만으로 승인·거절·상세 확인이 가능하다.

### R4 — 관찰 모드 자동 운영 (코드 작업 + 시간 경과)

- 국내 거래일 장 시작 전 데이터 갱신과 전략 스캔을 자동 실행한다.
- 통과 종목만 장중 기록 대상으로 등록하고 API 호출량을 제한한다.
- 백테스트 예상 신호와 실시간 신호, 예상 체결가와 관찰 가격을 매일 기록한다.
- 20거래일 진행률과 누락일, 신호 일치율, 가격 편차를 화면에 표시한다.
- 휴장일, 장외 시간과 중복 스케줄 실행은 건너뛴다.

완료 기준:

- 코드와 자동화 테스트를 먼저 통과한다.
- 실제로 서로 다른 20거래일 데이터가 쌓여야 현장 검증을 완료 처리한다.
- 누락 또는 중복 관찰 데이터가 있으면 원인과 재수집 가능 여부가 표시된다.

### R5 — 키움 모의투자 어댑터 (코드 작업 + 외부 검증)

- 공통 `BrokerAdapter` 아래에 로컬 PAPER와 키움 모의투자 구현을 분리한다.
- 현물 매수·보유 수량 내 매도, 정정, 취소, 미체결·체결·잔고 조회만 표준 모델로 매핑한다.
- 호출 제한, 인증 만료, 타임아웃, 재시도와 중복 응답을 처리한다.
- 시작 시 로컬 주문과 키움 미체결·체결·잔고를 대사하고 불일치 시 주문을 차단한다.
- 기본 테스트는 픽스처로 실행하고 실제 모의 서버 호출은 명시적인 프로필에서만 허용한다.

완료 기준:

- 코드 계약과 장애 시나리오 테스트를 모두 통과한다.
- 키움 모의투자에서 최소 수량으로 부분 체결·미체결·정정·취소·재시작 복구를 확인한다.
- 주문·체결·잔고 대사 불일치가 0건이어야 한다.

### R6 — 제한적 실계좌 검토 (별도 사용자 결정)

- R1~R5와 실제 20거래일 관찰이 모두 완료되기 전에는 시작하지 않는다.
- 최초에는 후보 알림과 사용자 수동 승인만 사용한다.
- 한 종목, 하루 최대 주문 수와 최소 금액을 고정하고 자동 확대하지 않는다.
- 실현 슬리피지, 비용 후 기대값, 주문 오류와 손실 한도를 매일 확인한다.
- 기준 이탈, 데이터 장애 또는 대사 불일치 발생 시 즉시 `SIGNAL_ONLY`로 중단한다.

실계좌 활성화는 코드 완성만으로 결정하지 않는다. 별도 체크리스트 검토와 사용자의 명시적인 승인이 필요하다.

## 바로 진행할 코드 작업 순서

1. 현물 PAPER 포지션·청산 상태 모델
2. 수동 청산 승인과 보유 수량 내 PAPER 매도
3. 손절·익절·최대 보유기간 자동 판정
4. 거래 사이클별 비용 후 성과 계산
5. 진입·보유·청산·완료 통합 화면
6. 관찰 스케줄러와 20거래일 진행 화면
7. 현물 전용 `BrokerAdapter`와 키움 모의투자 픽스처

선물·옵션·공매도 관련 기능은 위 순서에 포함하지 않으며 향후 확장 항목으로도 두지 않는다.

아직 필요한 핵심:

- 장중 체결강도 판단에 필요한 분봉·실시간 시세

## 단계별 실행 계획

### M0 — 전략 명세와 데이터 신뢰성 (P0)

- 전략 정의를 버전 관리한다.
  - 예: `strategyVersion`, 대상 시장, 제외 종목, 각 조건의 기간·임계값, 진입·청산 규칙
- 일봉 원천 데이터 품질 보고서를 만든다.
  - 누락 거래일, 중복, 0 가격·거래량, 비정상 급변, 최근 갱신 시각을 검사한다.
- 수정주가와 액면분할·배당·권리락 등 기업행사를 반영한다.
- 당시 상장 종목 집합을 보존해 상장폐지 종목도 백테스트에 포함한다.
- ETF·ETN·스팩·관리·정리매매·거래정지·우선주 등의 포함 정책을 명시한다.

완료 기준:

- 임의 종목 20개와 임의 거래일 20일을 원천 자료와 대조한다.
- 같은 데이터·전략 버전으로 실행하면 후보와 점수가 항상 동일하다.
- 데이터 누락이 있으면 매매 신호를 만들지 않고 이유를 기록한다.

### M1 — 연구용 후보 탐지기 (P0)

- 현재 규칙을 개별 특징값으로 저장한다.
  - 과거 고점 대비 낙폭, 박스 폭·기간, 거래량 스파이크 횟수, 돌파율, 돌파 거래량 배수, 눌림률, 조정 거래량 비율
- 유동성·매매 가능성 필터를 추가한다.
  - 최소 가격, 평균 거래대금, 호가 간격 또는 스프레드, 거래정지 여부, 상·하한가 상태
- 시장 환경 특징을 추가한다.
  - 코스피·코스닥 추세, 시장 변동성, 업종 상대강도, 시장 전체 상승 종목 비율
- 후보가 된 시점의 입력값·점수·전략 버전을 스냅샷으로 저장한다.
- ‘급등’을 여러 예측 구간과 목표로 라벨링한다.
  - 예: 신호 다음 5/10/20거래일 내 최대 상승률과 먼저 도달한 손절·익절 가격

완료 기준:

- 화면에 점수뿐 아니라 통과·탈락 조건과 데이터 기준 시각이 표시된다.
- 후보가 적거나 없는 날도 정상 결과로 처리한다.
- 결과를 CSV로 내보내 독립적으로 재계산할 수 있다.

### M2 — 백테스트 엔진 (P0)

- 신호 시점에 알 수 있었던 데이터만 사용하는 이벤트 기반 백테스트를 구현한다.
- 진입은 신호 다음 거래 가능 시점으로 처리하고 지정가·시장가 체결 모델을 분리한다.
- 수수료, 세금, 슬리피지, 호가 제한, 거래량 대비 주문 크기를 반영한다.
- 익절·손절·보유기간·추적손절과 장중 동시 충족 시 보수적인 체결 순서를 정의한다.
- 종목 중복 보유, 현금 부족, 최대 보유 수, 재진입 대기 기간을 반영한다.
- 기준 전략(현금 보유, 코스피·코스닥 지수, 단순 돌파)과 비교한다.

필수 지표:

- 후보 탐지: Precision@K, 재현율, PR-AUC, 후보 수와 오탐률
- 매매 성과: 거래비용 후 기대값, 승률, 평균 손익비, Profit Factor, CAGR
- 위험: 최대 낙폭, 변동성, 연속 손실, 일·월 최악 손실, 종목·업종 집중도
- 현실성: 회전율, 평균 체결 금액, 거래대금 대비 주문 비율, 슬리피지 민감도

완료 기준:

- 학습·조정 기간과 최종 검증 기간을 시간순으로 완전히 분리한다.
- 여러 상승·하락·횡보 장세의 워크포워드 구간에서 비용 후 기대값이 양수다.
- 임계값을 조금 바꿔도 결과가 붕괴하지 않으며 최대 낙폭이 사전 한도 안에 있다.
- 결과가 좋지 않으면 다음 단계로 넘어가지 않고 전략을 폐기하거나 다시 정의한다.

### M3 — 장중 데이터와 신호 확정 (P1)

- 실시간 또는 분봉 데이터를 저장하고 재생할 수 있게 한다.
- 장중 급등 추격을 피하기 위한 체결 조건을 검증한다.
  - 스프레드, 거래량·거래대금, 돌파 후 유지 시간, 변동성, 호가 잔량 급변
- 종가 기준 후보와 장중 진입 신호를 분리한다.
- 데이터 연결 끊김, 지연, 순서 역전, 중복 이벤트를 감지한다.

완료 기준:

- 저장된 장중 데이터를 같은 순서로 재생하면 동일 주문 의사결정이 나온다.
- 데이터가 오래됐거나 끊기면 신규 주문이 자동 차단된다.

### M4 — 주문·위험관리 코어 (P0, 주문은 아직 비활성)

- 주문 상태 머신을 구현한다.
  - `CREATED → SUBMITTED → ACKNOWLEDGED → PARTIALLY_FILLED → FILLED/CANCELED/REJECTED`
- 모든 주문에 고유 의사결정 ID를 부여해 재시작·재시도 시 중복 주문을 막는다.
- 미체결 조회, 정정·취소, 체결 내역, 잔고를 주기적으로 대사한다.
- 주문 가능 수량과 현금을 주문 직전에 다시 확인한다.
- 하드 리스크 한도를 설정한다.
  - 종목당 최대 비중, 총 투자 비중, 일일 손실, 누적 낙폭, 최대 동시 보유, 연속 주문 실패
- 킬 스위치를 제공한다.
  - 신규 주문 중단, 미체결 일괄 취소, 수동 승인 없이는 재개 불가
- 기본 모드는 `SIGNAL_ONLY`, 다음은 `PAPER`, 마지막만 `LIVE`로 두고 실서버 주문은 별도 환경변수와 화면 확인을 모두 요구한다.

완료 기준:

- 네트워크 타임아웃과 프로세스 재시작을 반복해도 중복 주문이 없다.
- 서버 기록, 키움 미체결·체결·잔고가 자동 대사된다.
- 모든 진입·청산·거부 결정에 당시 데이터와 이유가 남는다.

### M5 — 관찰 모드와 모의투자 (P0)

- 2~4주 동안 주문 없이 실시간 신호만 기록한다.
- 기록된 시점의 예상 체결가와 실제 이후 가격을 비교해 백테스트 괴리를 측정한다.
- 키움 모의투자에서 작은 고정 주문 크기로 주문 전 과정을 검증한다.
- 장 시작·마감, VI, 상·하한가, 거래정지, 부분 체결, 미체결, 인증 만료를 시나리오 테스트한다.

완료 기준:

- 최소 20거래일 또는 사전에 정한 최소 신호 수를 확보한다.
- 신호 누락·중복 주문이 없고 대사 불일치가 0건이다.
- 모의 성과가 백테스트 허용 오차 안이며 손실 한도가 항상 작동한다.

키움은 실제 적용 전에 모의투자로 충분히 테스트할 것을 공식 안내한다. 모의투자 국내주식은 KRX만 주문·계좌조회가 가능하며 NXT는 지원하지 않는다는 차이를 감안한다.

### M6 — 제한적 실매매 (P2, 수동 승인 필요)

- 첫 단계는 후보 알림과 수동 주문 승인만 사용한다.
- 이후에도 최소 주문 금액·1종목·1일 주문 횟수 제한으로 시작한다.
- 매주 백테스트 대비 실현 슬리피지, 신호 분포 변화, 손익과 오류를 검토한다.
- 데이터·성과 분포가 기준에서 벗어나면 자동으로 `SIGNAL_ONLY`로 강등한다.
- 주문 규모 확대는 별도 결정으로 취급하며 자동 확대하지 않는다.

## 1차 전략 가설

현재 구현 조건은 아래 범위에서 탐색하되, 최종값은 워크포워드 검증으로 정한다.

| 구간 | 후보 특징 | 초기 탐색 범위 |
| --- | --- | --- |
| 급락 | 과거 고점 대비 하락 | -20% ~ -60% |
| 횡보 | 박스 기간 | 40 ~ 120거래일 |
| 횡보 | 박스 폭 | 10% ~ 30% |
| 수급 흔적 | 중앙 거래량 대비 급증 | 2 ~ 5배, 2회 이상 |
| 초기 돌파 | 전일 대비 상승 | 3% ~ 15% |
| 돌파 확인 | 박스 상단 돌파·거래량 | 상단 1% 이상, 거래량 2배 이상 |
| 눌림 | 돌파 후 고점 대비 조정 | -2% ~ -12% |
| 조정 건전성 | 돌파일 대비 조정 거래량 | 70% 이하 |

이 값은 매수 추천 기준이 아니라 검증할 탐색 공간이다. 한 가지 최적값을 찾기보다 여러 기간에서 안정적인 범위를 선택한다.

## 구현 순서

1. 데이터 품질 검사와 전략 버전·신호 스냅샷
2. 백테스트 데이터 모델과 단일 종목 체결 엔진
3. 전체 시장 포트폴리오 백테스트와 결과 화면
4. 위험 한도·킬 스위치·주문 상태 머신
5. 장중 데이터 기록·재생
6. 관찰 모드
7. 키움 모의투자
8. 사용자 수동 승인 기반의 제한적 실매매

## 공식 API 제약 메모

- 키움 REST API는 운영 `https://api.kiwoom.com`, 모의 `https://mockapi.kiwoom.com`을 구분한다.
- 국내주식 주문·조회 TR은 계좌별 토큰 기준 초당 5회이며, 모의투자는 TR별 초당 1회 제한이 안내되어 있다.
- 국내주식 매수 주문은 `kt10000`, 미체결·체결 조회 API도 별도로 제공된다.
- 실시간 시세는 세션당 종목 수 제한이 있으므로 전체 시장은 일봉·순위로 좁힌 뒤 소수 후보만 구독한다.

참고: [키움 REST API 소개·이용 제한](https://openapi.kiwoom.com/intro?dummyVal=0), [키움 REST API 가이드](https://openapi.kiwoom.com/guide/apiguide)

## 주의

백테스트와 모의투자 수익은 실거래 수익을 보장하지 않는다. 급등 후보 전략은 가격 충격, VI, 상한가, 호가 공백과 급격한 반전 위험이 크므로 자동 주문보다 손실 제한과 중단 기능을 먼저 완성한다.
