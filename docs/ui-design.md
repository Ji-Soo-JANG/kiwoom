# UI 설계서

최종 수정일: 2026-08-29
문서 상태: 초안 기준선 v0.1

## 1. UI 목표

사용자가 전문적인 주문 시스템 용어를 모두 알지 않아도 지금 서버가 안전한지, 실제 주문이 가능한지, 어떤 종목을 왜 선택했는지, 계좌에 무엇이 보유되어 있는지를 빠르게 이해하게 한다. 수익 정보보다 모드, 위험 상태와 데이터 시각을 먼저 보여준다.

## 2. 공통 화면 구조

```text
┌──────────────────────────────────────────────────────────┐
│ Kiwoom 자동매매  [PAPER/LIVE] [자동매매 OFF] [정상/중지] │
│ 데이터 기준 08/29 08:52 · 계좌 동기화 3초 전              │
├──────────┬───────────────────────────────────────────────┤
│ 대시보드 │ 현재 화면                                     │
│ 종목발견 │                                               │
│ 차트     │                                               │
│ 자동매매 │                                               │
│ 계좌     │                                               │
│ 성과     │                                               │
│ 운영상태 │                                               │
│ 설정     │                                               │
└──────────┴───────────────────────────────────────────────┘
```

상단 상태 막대는 모든 화면에 고정한다. PAPER와 LIVE는 색상만으로 구별하지 않고 문구와 아이콘을 함께 사용한다. LIVE 실제 주문 가능 상태에서는 화면 가장자리에 지속적인 경고 표시를 둔다.

## 3. 화면 목록

### UI-01 대시보드

목적: 오늘 자동매매 상태와 필요한 조치를 한눈에 확인한다.

- 모드, ON/OFF, 선택 전략과 전략 승격 상태
- 장 상태와 다음 자동 작업
- 데이터 최신성, 키움 연결, DB, 계좌 대사 상태
- 보유 종목, 총 노출, 당일 손익, 누적 낙폭과 위험 한도
- 오늘 후보·주문·체결·차단 건수
- 오류 발생 시 “왜 중지됐는지”와 “다음에 무엇을 해야 하는지”
- 오늘·이번 달 손실 예산 사용량과 시장 상태

### UI-02 종목 발견

목적: 현재 핵심 패턴에 해당하는 후보를 비교한다.

```text
전략: [급락-동적 안정-회복-눌림 vX]  기준일: [최신]  [다시 분석]

[후보 12] [데이터 제외 8] [조건 탈락 2,340]
┌──────┬────┬────────┬────────┬────────┬────────┬──────┐
│ 종목 │점수│ 급락   │안정구간│거래량  │회복/눌림│ 상태 │
├──────┼────┼────────┼────────┼────────┼────────┼──────┤
│ A사  │ 86 │-42%    │23.02~  │5회     │21%/-6% │현재  │
└──────┴────┴────────┴────────┴────────┴────────┴──────┘
```

- 안정 구간 기간은 보여주되 “오래될수록 무조건 좋음”으로 표현하지 않는다.
- 후보 카드에는 선택 이유 태그와 주요 위험 태그를 같이 표시한다.
- 패턴 발견, 진입 대기, 주문 가능, 보류, 무효, 위험 차단 상태를 구분한다.
- 탈락 종목도 코드·종목명 검색 시 거절 사유를 볼 수 있다.
- 목록 클릭 시 UI-03 차트로 이동하며 종목과 전략 실행을 유지한다.

### UI-03 종목 차트·판정 상세

목적: 전략 판단을 사람이 검토하고 오류를 발견할 수 있게 한다.

- 일봉 가격·거래량 차트
- 급락, 안정, 회복, 눌림 구간의 반투명 오버레이
- 각 구간 시작·끝 날짜와 핵심 특징값
- 현재가 위치, 진입 검토 가격, 무효화 가격과 예상 위험
- 선택·거절 근거 전체 목록
- 최대 진입가, 무효화 가격, 주당 예상 손실과 청산 계획
- 사용 데이터 기준일, 전략 버전, 스캔 실행 ID
- 같은 종목의 과거 신호와 PAPER 결과(현재 신호와 시각적으로 분리)

### UI-04 자동매매 제어

목적: 운전 모드, 전략과 위험 한도를 안전하게 설정한다.

```text
자동매매                         [ OFF ●──── ON ]
실행 환경                        ( ) PAPER  ( ) LIVE
선택 전략                        [전략명 vX        ▼]
전략 상태                        모의투자 승인 전 / LIVE 선택 불가

위험 한도
주문당 금액 [      ]  최대 보유 [ ]  일 손실 [   %]
총 투자비율 [   %]  월 손실 [   %]  누적 낙폭 [   %]

준비 검사  데이터 ✓  계좌 ✓  대사 ✓  전략 ✗  키움 ✓
                                           [자동매매 시작]
```

- OFF는 즉시 신규 매수를 중단하지만 기존 주문·포지션 처리 정책을 안내한다.
- LIVE 선택 시 계좌 별칭, 주문 가능 금액, 위험 한도와 실제 주문임을 다시 보여준다.
- LIVE 시작 버튼은 준비 검사를 모두 통과해야 활성화한다.
- 확인창은 사용자가 지정된 확인 문구를 입력하게 하며 결과를 감사 기록에 남긴다.
- 킬 스위치 해제는 일반 ON/OFF와 분리한다.
- 목표 수익은 보고용으로 표시하되 주문 규모를 자동 확대하는 설정은 제공하지 않는다.
- 전략 승격 단계와 현재 모드에서 선택할 수 없는 이유를 표시한다.

### UI-05 계좌·포지션·주문

목적: 키움 계좌를 기준으로 현재 자산과 주문 상태를 확인한다.

탭:

- `계좌 요약`: 현금, 주문 가능 금액, 평가금액, 총 노출, 손익
- `보유 종목`: 수량, 평단, 현재가, 전략, 손절·청산 상태, 미실현 손익
- `미체결 주문`: 주문 상태, 잔여 수량, 경과 시간, 정정·취소 상태
- `체결 내역`: 예상가·체결가, 수수료·세금, 슬리피지
- `대사 문제`: 로컬과 브로커 차이, 심각도, 신규 매수 차단 여부

수동으로 만든 포트폴리오는 실전 계좌 화면에 섞지 않는다. 분석용 관심 목록이 필요하면 별도 명칭과 화면으로 제공한다.

### UI-06 전략 성과

목적: 전략을 느낌이 아니라 데이터로 비교한다.

- 백테스트, 워크포워드, PAPER, 모의투자, 실전 결과를 출처별 분리
- 순수익률, 기대값, 승률, 손익비, Profit Factor, 최대 낙폭, 거래 수
- 수수료·세금·슬리피지 전후 비교
- 기간·시장 상태별 결과와 전략 버전 비교
- 승격 기준 통과·실패 사유
- 후보→주문→체결→청산의 이탈 원인

표본이 적을 때는 수익률보다 “판단하기에 데이터가 부족함”을 먼저 표시한다.

### UI-07 운영 상태

목적: 서버를 켜두었을 때 자동 작업과 장애를 관리한다.

- 오늘 단계 타임라인: 기동, 데이터, 품질, 대사, 스캔, 장중 감시, 장후 처리
- 키움 인증·호출 제한·최근 성공 시각
- 데이터 신선도와 품질 차단 종목
- 스케줄 다음 실행 시각과 마지막 결과
- 킬 스위치와 차단 원인
- 안전 종료 가능 여부
- 사용자용 해결 안내와 개발자용 trace ID 접기 영역

### UI-08 설정

- 전략 기본 선택과 알림
- 위험 한도(변경 이력 포함)
- 장 전·장 후 실행 시각
- 데이터 보관·백업 상태
- 계좌 별칭과 키움 환경 상태(비밀값 자체는 표시하지 않음)
- 개인 손실 예산 정책의 버전과 변경 이력

### UI-09 장 전 준비 검사

- 데이터 최신성·품질, 시장 거래일, 키움 인증, 계좌·미체결 대사
- 시장 상태 `정상/주의/위험/확인 불가`
- 전략 승격 단계, 개인 손실 예산과 실제 주문 가능 여부
- 실패 항목의 원인, 신규 매수 차단 여부와 해결 안내
- 준비 검사가 끝나기 전 LIVE 시작 버튼 비활성화

## 4. 상태 표현

모든 데이터 영역은 다음 상태를 가진다.

- `로딩`: 기존 데이터를 지우지 않고 갱신 중임을 표시
- `빈 결과`: 정상적으로 후보가 없는 것과 아직 스캔하지 않은 것을 구분
- `부분 결과`: 일부 종목 실패 수와 제외 이유 제공
- `오류`: 사용자 설명, 재시도 가능 여부, trace ID 제공
- `오래된 데이터`: 마지막 성공 시각과 신규 매수 차단 여부 표시
- `권한/준비 미완료`: 필요한 설정과 이동 버튼 제공

502 같은 프록시 오류는 단순 “요청 실패”가 아니라 백엔드 미실행, 키움 API 실패, timeout 등 확인 가능한 범위에서 원인을 분리해 보여준다.

## 5. 색상과 접근성

- 일반 본문은 흰 배경에서 충분한 명도 대비를 확보하며 흰색 글자를 사용하지 않는다.
- 상승·하락 색상만으로 의미를 전달하지 않고 `+/-`, 아이콘과 문구를 함께 쓴다.
- PAPER는 파랑 계열, LIVE는 주황/적색 경고 계열을 쓰되 텍스트 라벨을 유지한다.
- 키보드만으로 탭·버튼·표 행에 접근 가능해야 한다.
- 토글에는 상태를 나타내는 텍스트와 `aria-checked`를 제공한다.
- 차트 오버레이는 범례와 패턴 또는 선 형태 차이를 함께 제공한다.
- 모바일에서는 조회 중심으로 제공하고 LIVE 시작·위험 변경은 오조작 방지를 위해 추가 확인한다.

## 6. 확인과 위험 조작

| 조작 | 확인 수준 |
|---|---|
| PAPER ON | 변경 요약 확인 |
| PAPER OFF | 기존 포지션 처리 정책 안내 |
| LIVE ARM | 계좌·전략·위험 한도 요약 + 확인 문구 |
| LIVE START | 최신 준비 검사 통과 + 실제 주문 경고 |
| LIVE OFF | 신규 주문 중단 시점과 기존 주문 상태 안내 |
| 킬 스위치 해제 | 원인 해소 확인 + 별도 확인 문구 |
| 위험 한도 확대 | 변경 전후 값 + 재인증 또는 확인 문구 |

## 7. 화면과 API 연결

| 화면 | 주요 데이터/API |
|---|---|
| 대시보드 | automation, readiness, account summary, daily performance |
| 종목 발견 | strategy scan, candidate signals, rejection reasons |
| 차트 | daily candles, signal feature snapshot, pattern dates |
| 자동매매 | strategies, automation state, readiness, risk limits |
| 계좌 | broker account, positions, orders, fills, reconciliation |
| 성과 | backtest, walk-forward, paper/live performance |
| 운영 상태 | automation runs, quality, scheduler, health, audit summary |

## 8. UI 완료 기준

- PAPER와 LIVE, 실제 주문 가능 여부를 어떤 화면에서도 혼동하지 않는다.
- 자동매매 ON/OFF와 현재 중지 사유를 두 번 이내 조작으로 찾는다.
- 후보를 클릭해 차트와 각 패턴 구간·판정 근거를 확인할 수 있다.
- 계좌 화면은 브로커 기준 갱신 시각과 대사 상태를 표시한다.
- 로딩·빈 결과·오래된 데이터·부분 실패·서버 오류가 서로 다른 안내로 표시된다.
- 실전 시작, 위험 확대, 킬 스위치 해제는 우발적 클릭 한 번으로 실행되지 않는다.
