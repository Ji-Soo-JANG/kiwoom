# 전략연구팀 현행 분석 보고서

- 문서 ID: `DEPT-STR-001`
- 기준일: 2026-08-29
- 상태: 현행 조사 완료 / 제안 검토 필요
- 담당 요구사항: `STR-001`~`STR-005`, `ENT-001`, `ENT-002`, `EXT-001`, `MKT-001`, `RES-001`, `PRM-001`

## 1. 조사 목적

현재 코드가 사용자의 목표 패턴인 `급락 → 안정 구간 → 간헐적 거래량 증가 → 최근 부분 회복 → 현재 눌림`을 어떻게 판정하는지 확인하고, 실전 자동매매 전략으로 발전시키기 전에 유지·격리·수정할 부분을 구분한다. 이 문서는 구현 승인이 아니며 코드 변경을 포함하지 않는다.

## 2. 현재 구현(사실)

### 2.1 전략 구성

| 구성 | 역할 | 현행 상태 |
|---|---|---|
| `StockStrategy` | 전략 공통 계약 | 버전 키, 필요 이력, 분석 메서드를 정의한다. |
| `StrategyRegistry` | 버전별 전략 선택 | 등록된 전략을 버전 키로 찾는다. |
| `CurrentRecoveryPullbackStrategy` | 운영 기본 전략 v3 | v2 평가 결과에 `currentPattern`을 필수 자격 조건으로 적용한다. |
| `MultiPeriodRecoveryPullbackStrategy` | 장기 회복·눌림 전략 v2 | 60·120·240·480·720·1200일 창을 각각 평가하고 최고 점수를 고른다. |
| `DropBaseBreakoutPullbackStrategy` | 이전 전략 | 고정 박스권과 돌파·눌림을 판정하는 레거시 전략이다. |
| `StrategyPatternDetector` | 독립 레거시 탐지기 | 서비스 전략 레지스트리를 사용하지 않으며 백테스트 엔진에서 직접 사용한다. |
| `StrategyScanService` | 전체 종목 스캔 | DB 일봉과 시점 기준 유니버스를 사용해 후보를 계산하고 스냅샷을 저장한다. |

현재 v2/v3의 주요 규칙은 다음과 같다.

- 필요 이력: 1,500일
- 급락: 안정 구간 직전 30일 고점 대비 안정 구간 저가가 30% 이상 하락
- 안정 구간: 10·90 분위 가격 범위, 범위 내 체류율 80%, 단순 시작-끝 기울기 사용
- 거래량: 안정 구간 중앙값의 2.5배 이상이 2회 이상
- 부분 회복: 이전 하락 절대폭의 15~30%
- 현재 눌림: 회복 고점 대비 4~12% 하락하고 안정 구간 상단의 97% 이상 유지
- 눌림 거래량: 회복 이후 평균 거래량이 해당 구간 최대 거래량의 65% 이하
- 통과: 총점 75점 이상이면서 모든 핵심 조건을 만족하고 최신 분석 구간이 현재 패턴이어야 한다.

`V21`~`V24` 마이그레이션은 전략 정의와 v2/v3 등록, 현재 스윙 전략 선택을 DB에 남긴다. `V9`는 스캔과 후보 결과를 저장하지만 주요 수치와 `matched_conditions` 중심이며 각 구간의 실제 시작·종료일은 저장하지 않는다.

### 2.2 핵심 흐름

```text
전략 정의에서 선택된 버전
→ 시점 기준 종목 목록 조회
→ 품질 차단 종목 제외
→ 종목별 DB 일봉 조회
→ StrategyRegistry 전략 분석
→ 점수·자격·조건 생성
→ strategy_scan / strategy_candidate_snapshot 저장
→ 제한 매매 후보 생성 흐름으로 전달
```

## 3. 잘된 점

- 전략 인터페이스와 레지스트리가 있어 전략 버전 공존 기반이 있다(`STR-004`).
- 최신 일봉까지 이어지는 패턴만 허용하도록 v3이 명시적으로 분리돼 있다(`STR-003`).
- 고정 단일 기간이 아니라 여러 장·단기 창을 비교하여 사용자 의도를 부분적으로 반영했다.
- 평균 대신 분위 가격과 중앙 거래량을 사용해 극단값 영향을 일부 줄였다.
- 후보에 점수와 사람이 읽을 수 있는 조건을 제공한다(`STR-005`, `NFR-008`).
- 합성 시계열 테스트가 장기 안정 구간, 현재성, 이력 부족을 검증한다.
- 스캔이 외부 시세를 즉시 호출하지 않고 저장 일봉을 사용한다(`DAT-001`).

## 4. 문제와 기술 부채

### 4.1 요구사항과 직접 충돌

1. **안정 구간이 고정 창에 종속된다.** 60~1200일 중 하나를 고르는 방식이므로 상태 변화로 경계를 찾는 `STR-002`를 충족하지 않는다. 박스권 기간이 자격 조건보다 결과값이어야 한다는 사용자 결정과도 다르다.
2. **검증 엔진과 운영 전략이 다르다.** `EventBacktestEngine`은 `StrategyPatternDetector`를 직접 생성한다. 반면 운영 스캔은 `CurrentRecoveryPullbackStrategy` v3을 쓴다. 백테스트 결과의 `strategyVersion`은 v3으로 기록되지만 실제 신호는 레거시 알고리즘이므로 `RES-001`, `NFR-002`상 중대한 추적 오류다.
3. **구간 날짜와 구조화된 판정값이 없다.** 후보 DTO는 비율·점수·문자열만 제공한다. 급락·안정·회복·눌림의 시작·종료일과 개별 게이트가 저장되지 않아 `STR-001`, `STR-005` 완료 기준에 미달한다.

### 4.2 연구상 한계

- 급락 직전 30일, 최근 돌파 탐색 15일, 회복 15~30%, 눌림 4~12%가 코드 상수다. 전략 정의 DB의 `parameters_json`과 실제 실행 파라미터가 연결되지 않는다.
- 안정성 기울기는 첫 종가와 마지막 종가만 사용해 구간 내부 추세와 구조 변화를 놓칠 수 있다.
- 거래량 급증은 횟수만 보며 급증 간격, 가격 반응, 이후 가격 유지와 시장 대비 거래량을 보지 않는다.
- `pullbackVolume / peakVolume`은 눌림 거래량을 회복 고점일 거래량과 비교하는 정의가 아니며, 구간 최대값과 평균의 비교라 해석이 불안정하다.
- 점수와 필수 조건이 함께 존재하지만 점수 75점의 통계적 근거가 없다. 필수 게이트와 순위 점수를 더 명확히 분리해야 한다.
- 거래대금, 관리·정지·VI, 시장 및 업종 상태를 전략 진입 판정에 반영하지 않는다(`MKT-001`, `MKT-002`).
- 진입 무효화 가격, 최대 허용 진입가, 예상 손익비와 청산 전략이 신호에 없다(`ENT-001`, `ENT-002`, `EXT-001`).
- 합성 데이터 테스트 위주이며 실제 과거 기업행사·거래정지·갭·장기 횡보 사례 회귀 세트가 없다.

## 5. 분류 의견

### 유지·강화

- `StockStrategy`와 `StrategyRegistry`의 버전 선택 구조
- 현재성 필수 게이트와 DB 일봉 기반 스캔
- 점수·탈락 사유 제공 개념
- 전략 정의 및 스캔 스냅샷의 불변 이력

### 격리 또는 제거 검토

- `StrategyPatternDetector`: 새 검증 엔진이 운영 전략 계약을 사용한 뒤 제거 후보. 지금 제거하면 기존 백테스트가 깨지므로 먼저 교체해야 한다.
- `DropBaseBreakoutPullbackStrategy`: 재현용 이전 버전으로 보존하되 신규 운전 선택에서는 제외할지 결정해야 한다.
- `boxRangeDays`: 동적 전략에서는 사업 파라미터로 제거하고, 레거시 재현 요청에만 유지하는 방안을 권고한다.

### 수정 필요

- 동적 상태 구간 탐지기를 신규 불변 전략 버전으로 구현
- 구간 경계·특징·게이트·거절 코드의 구조화
- 전략 DB 파라미터와 실행 코드의 실제 결합
- 운영·백테스트·워크포워드가 동일 전략 인스턴스와 버전을 사용하도록 통합
- 후보와 주문 가능한 진입 계획을 분리

## 7. 타 부서 의존성과 조율 요청

- **데이터팀:** 수정주가의 실제 의미, 충분한 장기 이력, 상장폐지 포함 과거 유니버스, 거래정지·관리 상태와 업종 데이터가 필요하다.
- **성과검증팀:** 동적 탐지기를 운영과 동일한 코드로 미래 누수 없이 평가하고 파라미터 안정성을 확인해야 한다.
- **위험관리팀:** 신호와 진입을 분리하고 무효화 가격·종목당 손실 예산의 책임 경계를 정해야 한다.
- **매매시스템팀:** 장중 진입 가능 가격, 유동성, 부분 체결이 전략 가정과 일치하는지 검토해야 한다.
- **UI팀:** 구간 경계와 거절 사유를 차트·목록에서 설명할 표현 계약이 필요하다.

## 8. 미결정 쟁점

- 동적 안정 구간의 변화점 알고리즘과 최소 통계 표본 수
- 급락의 크기·속도, 부분 회복, 눌림의 탐색 범위
- 현재성 허용 거래일 수와 회복 이후 최대 대기 기간
- ETF·ETN·우선주·SPAC·관리종목 포함 여부
- 시장·업종 필터가 필수 차단인지 주문 크기 조정인지
- 손절, 추적 청산, 시간 청산의 조합과 우선순위
