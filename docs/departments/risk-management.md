# 위험관리팀 현행 조사 보고서

- 문서 상태: 부서 조사 완료 / 부서 간 검토 대기
- 조사 기준일: 2026-08-29
- 담당 부서: 위험관리팀
- 연결 요구사항: CAP-001~002, ENT-001~002, EXT-001~002, MKT-001~002, PRM-001~003, TRD-002~004, DAT-003~004, NFR-002·008
- 조사 범위: PAPER 위험 한도, 킬 스위치, 제한 매매, 성과 저하 감시, 청산, 자동매매 제어, 요구사항·안전 문서와 관련 테스트

## 1. 결론

현재 위험관리는 **PAPER 계좌의 정적 노출 한도와 킬 스위치** 수준이다. 종목당 10%, 총노출 50%, 일일 손실 2%, 최대낙폭 10%, 최대 5종목 기본값이 있고, 제한 매매에는 더 작은 고정 한도가 추가된다. 매도는 위험 축소로 보고 킬 스위치 중에도 허용한다.

그러나 자산 평가는 보유 종목의 **평균 체결가**를 사용하므로 실시간 평가손익과 갭 위험이 반영되지 않는다. 월간 손실, 거래당 손실 예산, 무효화 가격, 업종·상관 노출, 시장 위험 상태, 실계좌 브로커 대사도 없다. 따라서 현재 킬 스위치는 CAP-001의 실전 위험 통제 수단이 아니며 PAPER 검증 장치로만 인정해야 한다.

## 2. 현재 위험 통제

| 통제 | 현재 동작 | 한계 |
|---|---|---|
| 종목 비중 | 주문 후 종목가치/자산이 설정 비율 이하인지 검사 | 평균 체결가 기반 자산, 실시간 가격 미반영 |
| 총 노출 | 주문 후 총 보유가치/자산 검사 | 업종·상관·미체결 주문 노출 미반영 |
| 동시 보유 | 신규 종목 수 제한 | 계좌 외부 포지션을 모름 |
| 현금 | PAPER 현금보다 큰 매수 거부 | 수수료·세금·미체결 예약금 반영 제한 |
| 일일 손실 | day-start equity 대비 손실로 킬 스위치 | 시가평가가 없어 실질 손실 감지 지연 |
| 최대 낙폭 | peak equity 대비 낙폭으로 킬 스위치 | 동일 문제, 월/전략별 손실 없음 |
| 수동 킬 스위치 | 신규 매수 차단, 열린 PAPER 주문 취소 | 외부 주문·실계좌에는 영향 없음 |
| 수동 재개 | 확인 문구 후 기준 자산 재설정 | 독립 승인·원인 조치 증적 없음 |
| 성과 악화 | 5표본 이상 평균 절대 슬리피지 1% 초과 또는 평균 순수익 음수 시 중단 | 표본·통계 기준이 연구용 고정값 |
| 제한 매매 | 10만원, 1종목, 하루 2회 | 최종 실전 정책 아님 |
| 청산 | 손절·익절·최대보유일 | 구조 훼손·추적청산·시장 위험·갭 정책 부족 |

## 3. 위험 판정 흐름

### 신규 PAPER 매수

1. PAPER 계좌와 포지션을 읽고 자산·노출을 계산한다.
2. 일일 손실 또는 최대낙폭 위반이면 킬 스위치를 활성화한다.
3. 현금, 종목 비중, 총노출, 동시 보유 수를 검사한다.
4. 제한 매매 경로이면 주문액·하루 주문 수·1종목 제한을 추가 검사한다.
5. 통과한 주문만 PAPER 체결한다.

### 손실 한도 위반

1. `paper_account`에 킬 스위치 사유와 시각을 저장한다.
2. CREATED/SUBMITTED/ACKNOWLEDGED/PARTIALLY_FILLED 주문을 CANCELED로 전환한다.
3. 신규 BUY는 차단하고 SELL은 허용한다.

### 재개

확인 문구가 일치하면 현재 계산 자산을 새 일일·낙폭 기준으로 설정하고 재개한다. 원인 분석 완료, 데이터 신선도, 브로커 대사, 사용자 승인 여부는 현재 재개 조건에 포함되지 않는다.

## 4. 강점

- 위험 한도가 환경 설정으로 외부화되어 있고 양수 검증이 적용된다.
- 킬 스위치 상태와 사유가 DB에 남아 서버 재시작 후에도 유지된다.
- 위험 축소 매도를 신규 매수와 구분하는 fail-safe 방향이 반영됐다.
- 성과 저하가 자동 킬 스위치로 연결되어 무조건 계속 거래하지 않는다.
- 제한 매매가 성과를 이유로 주문 크기를 자동 확대하지 않는다.
- `LimitedTradingServiceTest`가 부정적 성과 5표본 후 자동 중단을 검증한다.
- 주문 상태 머신을 통해 킬 스위치가 진행 주문을 임의 상태 변경하지 못하도록 한다.

## 5. 문제와 기술 부채

### 5.1 실전 전 필수 차단사항

| 차단사항 | 필요한 통제 | 연결 요구사항 |
|---|---|---|
| 평균 체결가 기준 자산 평가 | 신선한 시세와 브로커 평가금액 기반 자산·손익 | CAP-001, DAT-004 |
| 거래당 손실 예산 없음 | 진입가·무효화가·슬리피지로 수량 계산 | ENT-002, CAP-001 |
| 월간 손실 및 연속 손실 정책 없음 | 월 손실·연속 손실·전략별 손실 한도 | CAP-001 |
| 시장·업종 위험 필터 없음 | 정상/주의/위험 상태와 신규 매수 차단 | MKT-001 |
| VI·거래정지·투자위험 확인 없음 | 주문 직전 거래 가능 상태 검사 | MKT-002 |
| 미체결 주문 위험 미합산 | 예약 현금·잠재 포지션·기존 매도 수량 포함 | TRD-003 |
| 브로커 원장 불일치 통제 없음 | 불일치 시 신규 매수 중단과 수동 해소 | TRD-004 |
| 전략 승격 상태 없음 | 미승격 전략의 PAPER/LIVE 선택 금지 | PRM-001~002 |
| 재개 권한·증적 부족 | 원인 해소·독립 승인·준비검사 후 재개 | NFR-002 |
| 갭·유동성·부분체결 위험 미모델링 | 최악 체결가와 잔여 위험 처리 | EXT-002 |

### 5.2 계산상 주의점

- `PaperRiskService.equity`는 `averagePrice × quantity`를 사용한다. 가격 하락이 발생해도 포지션 저장값이 바뀌지 않으면 일일 손실과 낙폭이 감지되지 않는다.
- 주문 전 금액은 `price × quantity`만 사용해 비용과 가격 미끄러짐 여유가 없다.
- 열린 매수 주문이 총 노출·현금에 예약되지 않는 구조라 외부 비동기 체결 모델로 확장하면 한도를 초과할 수 있다.
- 킬 스위치 활성화 시 로컬 상태를 CANCELED로 바꾸는 것만으로 외부 취소가 보장되지 않는다.
- 성과 악화 기준은 평균값만 사용해 꼬리 손실, 최대 역행폭, 표본 신뢰도, 시장 국면을 보지 않는다.
- 재개 시 peak/day-start 기준이 현재 자산으로 리셋되므로 승인 통제가 약하면 손실 한도를 반복 초기화할 수 있다.

## 6. 유지·수정·제외 제안

### 유지할 부분

- 기본 차단 모드와 신규 매수 fail-closed 원칙
- DB에 지속되는 킬 스위치 및 사유
- 종목·총노출·동시보유·일손실·낙폭의 다중 한도 구조
- 위험 축소 주문 허용 원칙
- 성과와 체결 품질의 지속 기록

### 수정할 부분

- 개인 운용 정책에 초기 원금, 일·월 최대 손실, 계좌 최대낙폭, 거래당 위험, 동시 보유, 연속 손실을 명시한다.
- 수량은 `허용 거래손실 / (진입가 - 무효화가 + 비용·슬리피지 버퍼)`로 계산하고 다른 한도 중 가장 작은 값으로 제한한다.
- 계좌·포지션·미체결을 브로커 원장으로 평가하고 시세가 오래되면 신규 매수를 차단한다.
- 업종·상관·시장 상태별 노출 한도를 추가한다.
- 진입 전 데이터 품질, 거래 가능 상태, 최대 진입가와 최소 기대 손익비를 통과시킨다.
- 킬 스위치를 원인별 단계로 나누고, 재개에는 원인 해소 증적과 사용자 승인을 요구한다.
- 매일 위험 스냅샷과 한도 변경 이력을 불변 감사 이벤트로 남긴다.
- 전략 승격 상태와 운전 단계별 최대 자금을 연결한다.

### 최종 정책으로 사용하지 않을 부분

- P2의 10만원·1종목·2회 고정값은 최소 실험 단계의 임시 값이다.
- 5표본 평균 손실만으로 전략 폐기나 실전 승격을 결정하지 않는다.
- 목표 수익 미달을 이유로 수량·빈도·위험 한도를 자동 확대하지 않는다.
- AI 제안을 검증·버전 승인 없이 주문 규칙에 적용하지 않는다.

| 관련 부서 | 필요한 입력/합의 |

| 매매시스템팀 | 미체결 예약, 부분체결, 외부 취소 확인, 실계좌 원장과 대사 |
| 데이터팀 | 시세 신선도, 시장·업종 지표, 거래정지·VI·투자 위험 상태 |

## 8. 위험관리팀 제안

1. 동적 전략 개발과 병행하여 `개인 운용 정책` 수치를 사용자 승인 안건으로 확정한다.
2. `진입 계획`을 독립 도메인으로 만들고 무효화가와 예상 최대손실 없이는 주문을 생성하지 않는다.
3. 시장 상태와 계좌 준비 상태를 주문 전 공통 위험 게이트로 둔다.
4. PAPER에서도 실시간 시가평가, 미체결 예약금, 비용·슬리피지를 먼저 적용한다.
5. 실전 승격 기준은 비용 후 기대값, 최대낙폭, 표본 수, 월별 안정성, 주문 오류율, 대사 성공률을 함께 사용한다.

## 9. 사용자 승인이 필요한 미결정 값

- 실제 투입 원금과 단계별 증액 한도
- 거래당 허용 손실액/비율
- 일간·월간 최대 손실과 계좌 최대낙폭
- 최대 동시 보유 수, 종목·업종·총노출 한도
- 연속 손실 시 축소·중단 기준
- 최소 기대 손익비와 최대 허용 슬리피지
- 킬 스위치 재개 승인자와 의무 대기 시간
- 갭 하락 시 가격 보호보다 즉시 위험 축소를 우선할 범위
