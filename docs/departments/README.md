# 부서별 프로젝트 분석 자료

기준일: 2026-08-29

이 디렉터리는 각 부서가 현재 프로젝트 구성과 코드를 직접 조사한 결과를 공유하는 공간이다. 문서는 구현 승인이 아니라 부서 간 검토와 PM 종합 판단을 위한 근거 자료다.

## 공통 작성 원칙

- 현재 구현, 목표 설계, 제안을 명확히 구분한다.
- 모든 주요 판단에 근거 코드·설정·DB·테스트·기존 문서를 연결한다.
- 결론뿐 아니라 위험, 반대 의견, 미결정 사항과 타 부서 확인 요청을 남긴다.
- `필요`, `수정`, `격리/제거 검토`, `보류` 항목을 구분한다.
- 사용자의 승인 전에는 제안 사항을 구현 확정으로 표현하지 않는다.
- 비밀키, 토큰, 계좌번호와 실제 개인정보는 문서에 기록하지 않는다.

## 문서 상태

현재 문서는 모두 `부서 조사 완료 / PM 검토` 상태다. PM 종합 보고의 승인 안건이 사용자에게 승인된 후에만 요건·설계 기준선이나 구현 계획으로 승격된다.

## 검토 의견 형식

다른 부서가 문서를 검토할 때 다음 정보를 남긴다.

```text
검토 부서:
검토한 문서와 버전:
결론: 찬성 / 조건부 찬성 / 반대 / 추가 자료 필요
근거:
영향:
요청 사항:
미해결 쟁점:
```

문서 원문을 임의로 덮어쓰기보다 PM 종합 검토의 쟁점표에 의견을 추가한다.
