# 실전 자동매매 기준 리팩터링 점검

최종 수정일: 2026-08-29

## 유지·강화할 부분

- DB 기반 일봉, 품질 검사와 시점 기준 종목 마스터
- 전략 레지스트리와 버전 정의, 신호 스냅샷
- 비용 반영 백테스트·워크포워드·관찰 데이터
- 주문 상태 머신, 멱등 의사결정 ID, PAPER 체결·포지션·성과
- 위험 한도, 킬 스위치, 스케줄과 장 후 대사
- 실제 키움 계좌 기반 포트폴리오 화면

## 수정할 부분

- 고정 60~1,200일 후보군을 상태 변화 기반 안정 구간 탐지로 교체한다.
- 현재 패턴 판정을 한국어 설명 문자열 검색에 의존하지 않고 구조화된 판정 코드로 변경한다.
- 패턴 후보와 주문 가능 진입 계획을 분리한다.
- 위험 한도를 비중 중심에서 무효화 가격·손실 예산 중심으로 보강한다.
- 시장 상태, 전략 승격, LIVE 준비 검사를 주문 전 게이트로 추가한다.
- 현재 PAPER 중심 이름과 모델을 계좌·브로커 중립 구조로 점진적으로 이동한다.
- UI 상단에 운전 모드·실주문 가능·시장 상태·손실 예산을 공통 표시한다.

## 제거하거나 격리할 부분

- 사용되지 않는 수동 포트폴리오 React 컴포넌트와 전용 호출 함수는 제거한다.
- 기존 수동 포트폴리오 DB와 백엔드 내보내기 기능은 사용자 데이터 보호를 위해 당분간 읽기 가능한 레거시로 유지한다.
- 자동매매와 관계없는 관심종목·일반 검색·비교·알림은 삭제하지 않되 핵심 운전 화면과 분리하고 개발 우선순위를 낮춘다.
- 빌드된 정적 파일은 소스가 아니므로 직접 수정하지 않고 프론트 빌드로만 갱신한다.

## 실행 순서

1. 죽은 프론트 코드와 중복 의존성 정리
2. 전략 판정 결과 구조화
3. 동적 안정 구간 전략 신규 버전 구현
4. 진입·청산 계획과 손실 예산 도입
5. 시장 상태·전략 승격·준비 검사 도입
6. 브로커 중립 OMS와 키움 모의·실전 어댑터 검증

대규모 삭제나 기존 DB 테이블 제거는 백업·내보내기와 API 사용 여부를 확인한 별도 마이그레이션에서 수행한다.
