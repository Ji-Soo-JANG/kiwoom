# P1 장중 검증 사용법

P1 기능은 관리자 로그인 세션에서 사용한다. 아래 기능은 기본적으로 외부 주문을 전송하지 않는다.

## 1. 장중 시세 기록과 재생

- `POST /api/intraday/events`: `sourceEventId`, 6자리 `code`, `eventTime`, `price`, `volume`을 저장한다.
- 동일한 `sourceEventId`를 다시 보내도 기존 이벤트를 반환한다.
- `GET /api/intraday/{code}/replay?from=...&to=...`: 시간순 원본과 재현 체크섬을 반환한다.
- `GET /api/intraday/{code}/bars?from=...&to=...`: 1분 OHLCV를 반환한다.
- 한 요청의 조회 범위는 최대 7일이다.

## 2. 20거래일 관찰

1. `POST /api/observations`로 전략 이름과 버전을 고정한 관찰을 만든다.
2. 매 거래일 `POST /api/observations/{id}/samples`로 백테스트 예상 신호와 실시간 신호를 기록한다.
3. `GET /api/observations/{id}`에서 일치율, 누락 신호, 예상 밖 신호와 평균 가격 편차를 확인한다.
4. 서로 다른 거래일 20일이 쌓일 때만 `complete`가 `true`가 된다. 같은 날짜·종목을 다시 기록하면 값만 갱신된다.

## 3. PAPER 주문 수명주기 사전 검증

`POST /api/trading/paper/verification`은 네트워크나 키움 서버를 호출하지 않고 다음 시나리오를 결정적으로 실행한다.

- 접수 후 미체결 유지
- 주문 수량·가격 정정
- 부분 체결
- 동일 체결 ID 재수신 무시
- 상태 복구 후 잔여 주문 취소

응답의 `passed=true`와 각 항목의 `true` 여부를 확인한다. 이것은 상태 머신 사전 검증이며 키움 모의투자 서버의 현장 검증을 대신하지 않는다.

## 현장 검증 완료 기준

- 실제 장중 후보 데이터가 서로 다른 거래일 기준 20일 이상 저장되어야 한다.
- 관찰 리포트의 차이를 검토해 허용 기준을 문서화해야 한다.
- 키움 모의투자 계정에서 최소 수량으로 각 주문 시나리오를 실행하고 주문·체결 내역을 대사해야 한다.
- 이 과정에서는 `LIVE` 모드를 사용하지 않는다.
